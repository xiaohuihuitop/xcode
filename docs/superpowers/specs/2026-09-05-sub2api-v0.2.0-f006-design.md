# Sub2API v0.2.0 F006 共享一致性同步设计

## 背景

XCode 已以 `v0.1.179` 为 Base、`v0.2.0` 为 Target 完成 F001 OpenAI/Codex Runtime 同步。F006 覆盖上游在共享重试、额度冷却、错误归类、安全审计和 reasoning 事实提取方面的修正。XCode 已删除官方 Group/Channel 产品模型，并用平台资产、平台模型规则、RuntimeBridge 和 ProductCore 计费链替代，因此 F006 不能整文件覆盖，只能在现有边界内做 Adapter 移植或等价验证。

固定同步身份：

- 上游：`Wei-Shaw/sub2api`
- Base：`v0.1.179`
- Target：`v0.2.0`
- Target commit：`aa236488351eb71e120fc2b6fb32e36b0374c918`
- Tag object：`dd07c4d8d484878e617c945cc8bacc304a5a6560`
- Archive SHA-256：`24a60d8cccb8b62ba184e5f8c4c636907af14e997be6a166ccd05e26d620bf9d`

## 方案选择

考虑过三种实施方式：

1. 整批复制官方 F006 文件。实现快，但会恢复 Group/Channel、覆盖 XCode 平台资产和计费语义，风险不可接受。
2. 只同步 Official Runtime zone。边界最保守，但本组主要缺口位于活动 Handler、Repository、SecurityAudit 和兼容转发路径，无法修复实际行为。
3. 按行为拆成 F006-A/B/C，在 XCode 活动路径中做窄 Adapter 移植，并用现有能力证明其余提交已等价。该方案改动最小、可逐组验证和回滚，采用此方案。

## 范围

### F006-A：重试、冷却与额度一致性

`UpstreamFailoverError` 增加请求内重试元数据：

- `SameAccountRetryDelay time.Duration`：错误指定的同账号等待时间；零值使用 500ms 默认值。
- `SameAccountRetryDeadline time.Time`：错误指定的重试截止时间；非零且未过期时允许按窗口重试。
- `SameAccountRetryMax int`：错误级硬上限；不得绕过账号显式配置的零重试预算。
- `RequestScopedTransient bool`：请求或模型容量型瞬态故障标记，用于指数退避及避免错误封禁账号。

Handler 在现有 `FailoverState` 内集中计算：

- 普通 `RetryableOnSameAccount` 仍受账号 `pool_mode_retry_count` 限制。
- 带 deadline 且没有错误级 max 的 OAuth 窗口型错误不受普通计数限制，但 deadline 过期后停止同号重试。
- 同时带 `SameAccountRetryMax` 时，max 是硬上限；账号配置为 0 时仍禁用重试。
- 显式 delay 优先；请求级瞬态错误使用 500ms、1s、2s、4s、8s 的封顶指数退避。
- 客户端取消、粘性会话缓存计费和现有切号计数语义保持不变。
- 请求级瞬态错误重试耗尽后可以切号，但不把所选账号临时封禁。

所有 Chat Completions、Responses、Messages、Gemini 兼容入口继续从实际选中账号读取重试配置。F006 不引入全局 429 配置，也不恢复已被上游 Revert 的可配置 429 策略。

管理员重置 API Key 账号额度时，Repository 用单条 `UPDATE` 同时：

- 清零 `quota_used`、`quota_daily_used`、`quota_weekly_used`；
- 清除额度窗口起始和重置字段；
- 清除账号级 `rate_limited_at`、`rate_limit_reset_at`；
- 保留 overload、临时不可调度、模型级冷却和其他调度状态；
- 账号不存在时返回 `ErrAccountNotFound`；
- 更新后发送现有 scheduler outbox 事件。

接口名称收敛为 `ResetQuotaUsedAndClearRateLimitCooldown`，避免调用方误以为只清额度。Admin service 直接调用原子接口，不串行调用通用 `ClearRateLimit`。

以下行为已有 XCode 等价实现，只补或运行回归，不新增产品逻辑：

- 404 `model_not_found` 当前不经过官方 `classifySelectionFailureError` 的 429 二次覆盖路径，继续保持 404。
- `AccountUsageService` 的 OAuth 和 Antigravity singleflight 回调都会在等待后再次检查缓存，避免重复额度探测。

### F006-B：路由、监控与安全审计

官方 Composite 精确账号别名不恢复。XCode 由平台模型规则优先解析精确模型，再把 resolved upstream model 交给平台账号池；增加或运行回归证明精确规则、平台隔离和 resolved target platform 不串池。

官方 Composite 监控平台归属映射为 XCode 的 `ResolvedTargetPlatform`、`PlatformAssetID` 和 Ops upstream error 事实。错误日志必须使用实际目标平台和账号，不恢复官方 Composite/Group 标识。

IPv6 代理批量输入的官方前端修正映射为 XCode 后端统一代理解析能力。现有 `proxyurl` 与 `proxyutil` 已覆盖 bracketed IPv6、代理 URL 和 dialer，F006 不改前端，只运行对应回归。

SecurityAudit 的 `ConfigManager.Reload` 不再每 5 秒记录一次 `prompt_guard.config_loaded`。仅在以下情况记录：

- 首次成功加载；
- `config_version` 改变；
- 独立设置中的 `RiskControlEnabled` 改变；
- 上一次加载失败后恢复成功。

`clearLoadError` 返回是否从错误状态恢复；成功 reload 始终更新快照和清除错误，但只有有新事实时写 info 日志。现有配置解析失败、fail-closed、token 解密告警和平台范围保持不变。

### F006-C：协议与 reasoning

F001 已同步空 tool name 保护，F006 将其记录为 `xcode_equivalent`，不重复修改。

Anthropic 兼容上游经 Chat Completions 或 Responses fallback 返回时，usage 中的 reasoning effort 必须按实际模型能力保留原生 `max`：

- 优先使用 mapped/upstream model，再使用原始请求 model，最后读取 body 中的 model。
- `gpt-5.6-*`、`deepseek-v4*`、`glm-*`、`kimi-*`、`moonshot-*` 和 `k3` 系列保留 `max`。
- 其他模型维持历史兼容，把 `max` 归一化为 `xhigh`。
- 只改变内部事实提取和 usage 结果，不修改请求体策略、公开 DTO、数据库 schema 或用户页面。

## 所有权与数据流

```text
请求 -> ProductCore 平台授权/模型规则
     -> 平台账号池选择
     -> Runtime Adapter 转发
     -> UpstreamFailoverError 重试元数据
     -> Handler 同号重试/切号
     -> Runtime usage facts
     -> ProductCore 计费与 usage sink
```

F006 只在箭头已有接口上补充内部事实。平台授权、模型售价、套餐、余额、计费和最终 usage 持久化继续由 ProductCore 拥有；Runtime 不直接写用户资产。

## 错误处理

- 客户端 context 取消立即结束，不触发新选号或误报账号耗尽。
- deadline 到期或计数上限耗尽后执行既有切号语义。
- 请求级瞬态错误不作为账号健康事实写入临时封禁。
- 原子额度重置失败原样返回，不执行部分清理或静默 fallback。
- SecurityAudit reload 失败保留现有错误状态；恢复成功记录一次恢复事件。
- 404 模型配置错误保持 `model_not_found`，不改写为 429。

## 测试与门禁

每个子组严格执行 RED -> GREEN -> 定向回归 -> rebaseline -> 双 validator -> 本地提交；任一子组失败时不叠加后续组。

F006-A 覆盖：

- delay、deadline、error max、账号零预算、请求级瞬态不封禁；
- Chat/Responses 等活动入口使用实际账号重试配置；
- Repository 原子 SQL、账号不存在、保留 overload；
- 404 和 quota singleflight 等价回归。

F006-B 覆盖：

- SecurityAudit 首载、无变化、版本变化、风控变化和错误恢复；
- 平台模型规则、目标平台 Ops 归属和 IPv6 代理解析现有回归。

F006-C 覆盖：

- Chat/Responses extractor 对原生 max、mapped model、body model 和旧模型 xhigh 的行为；
- 受影响 service 包测试。

最终门禁包括完整 backend unit、`go build ./cmd/server`、46 个同步工具测试、两套 validator、gofmt、`git diff --check`、敏感信息和范围审计。
