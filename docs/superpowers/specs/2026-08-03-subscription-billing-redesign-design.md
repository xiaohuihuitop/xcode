# Sub2API 订阅与计费重构设计

> **历史设计：** 本文件记录 `my2-v0.2.0` 的 Group/BillingProfile 过渡模型。
> 套餐实例快照、套餐优先和余额回退继续有效；Group 路由、BillingProfile 和迁移兼容
> 已被 `2026-08-06-platform-pool-account-adapter-design.md` 替代。

## 状态

- 状态：已实施；迁移、后端、前端和定向验证已于 2026-08-04 完成
- 日期：2026-08-03（设计确认），2026-08-04（实施完成）
- 开发分支：`my2.0`

迁移期仍保留 `Group` 的旧收费字段以兼容历史数据，但运行时分组查询会优先加载 `BillingProfile` 并投影为兼容字段；新建与编辑流程只写独立计费资料和套餐模型。

## 目标

将现有 `Group` 中混杂的账号路由、余额收费和订阅权益拆开。账号分组只负责上游账号与调度能力；余额使用 `BillingProfile`，订阅使用实例快照倍率，两者共享账号分组与基础价格目录，但不再存在用户专属余额倍率。

## 已确认规则

- 订阅套餐包含每日、每周、每月金额上限、有效期和套餐倍率。
- 订阅套餐倍率完全覆盖余额倍率与用户余额倍率。
- 用户专属余额倍率功能移除。
- 同一用户可在同一账号分组下拥有多条同套餐或不同套餐订阅。
- 同一账号分组的订阅按最早到期时间优先；到期时间相同时按创建时间优先。
- 一条订阅达到任一日、周、月上限或过期后，自动尝试下一条可用订阅；所有订阅不可用后才回退余额。
- 多个 API Key 分组时，保持现有“所有可用订阅优先，余额最后”的规则；跨分组顺序仍使用 API Key 允许分组的既有排序。
- 套餐模板的编辑只影响后续新发放订阅；现有订阅使用发放时保存的额度、有效期和倍率快照。

## 领域模型

### 1. ChannelGroup

当前 `Group` 演进为账号路由分组，负责：

- 平台、账号池、账号优先级和调度策略。
- 模型、端点、Live、Claude Code、隐私与 OAuth 等能力约束。
- 路由配置、降级分组和账号可用性。
- 分组状态与展示排序。

它不再保存任何面向用户的收费字段，包括余额倍率、订阅类型、订阅额度、有效期、高峰倍率、图片/视频价格和网页搜索价格。

### 2. BillingProfile

新增与 `ChannelGroup` 一对一的计费配置。它定义该账号分组共享的基础价格规则：

- 余额默认倍率。
- 图片、视频和网页搜索价格配置。
- 高峰时间与高峰价格策略。
- 其他未来新增的通用价格规则。

`BillingProfile` 不保存用户专属倍率，也不保存订阅额度或订阅有效期。

余额请求使用 `BillingProfile` 的余额倍率。套餐请求使用同一 `BillingProfile` 的基础价格目录，但其最终用户倍率由套餐实例提供，不能读取余额倍率。

账号的 `Account.rate_multiplier` 保持不变。它是上游成本核算参数，不是面向用户的售价倍率。

### 3. SubscriptionPlan

扩展现有用于支付与售卖的 `subscription_plans` 套餐模板，继续绑定一个 `ChannelGroup`：

| 字段 | 含义 |
| --- | --- |
| `id` | 套餐模板 ID |
| `group_id` | 共享账号分组 |
| `name`、`description`、`status` | 管理与展示信息 |
| `daily_limit_usd` | 每日金额上限，可为空 |
| `weekly_limit_usd` | 每周金额上限，可为空 |
| `monthly_limit_usd` | 每月金额上限，可为空 |
| `validity_days` | 发放后的有效天数 |
| `rate_multiplier` | 套餐独立倍率 |

现有价格、币种、在售状态和商品展示字段继续用于购买流程。套餐模板不保存账号、模型或路由配置；这些能力始终从 `ChannelGroup` 获取。

### 4. UserSubscription

`UserSubscription` 表示一次实际发放给用户的套餐权益。每次发放创建新记录，不再复用或延长同一个 `(user_id, group_id)` 记录。

保留并新增以下信息：

- 保留 `group_id`，用于快速调度、历史兼容和用量归属。
- 新增 `subscription_plan_id`，关联套餐模板。
- 保存 `daily_limit_usd_snapshot`、`weekly_limit_usd_snapshot`、`monthly_limit_usd_snapshot`、`rate_multiplier_snapshot`、`plan_name_snapshot`。
- 保留开始时间、到期时间、窗口起点、日周月已用金额、状态、发放人和备注。
- 删除现有 `(user_id, group_id)` 的部分唯一索引，改为支持同用户、同分组多条有效订阅。

套餐模板可被修改或停用，但已发放实例一律按快照继续计算。管理员需要调整既有权益时，使用显式的订阅调整操作，而不是修改模板。

## 请求与计费流程

```text
API Key 允许的 ChannelGroup 列表
  -> 按现有分组排序筛选平台、端点与可用性
  -> 批量读取用户在这些分组下的有效订阅实例
  -> 先寻找可用订阅：分组排序 -> 到期时间 -> 创建时间
  -> 订阅可用：使用 BillingProfile 基础价格 + subscription.rate_multiplier_snapshot
  -> 无可用订阅：选择第一个可用 ChannelGroup，使用 BillingProfile.balance_rate_multiplier
  -> 余额不足：返回余额不足错误
```

对于每一条订阅，日、周、月窗口重置、并发扣费、缓存失效和耗尽回退必须复用当前已验证的安全语义：

- 用量达到额度即不再参与新请求调度。
- 成功扣费后立即失效订阅认证 L1，并向其他实例发布失效通知。
- 请求最终费用确定后，允许一笔请求刚好耗尽剩余额度。

## 使用记录与展示

- 用量记录继续保存实际 `group_id`、`subscription_id`、最终倍率和最终费用。
- `subscription_id` 可追溯具体用户订阅实例；实例再关联套餐模板。
- 用户仪表盘和订阅页显示套餐快照名称、到期时间、三种额度窗口、已用与剩余金额。
- 管理端分别管理账号分组、余额计费规则和订阅套餐；API Key 页面仍只选择账号分组。

## 移除用户专属余额倍率

现有 `user_group_rate_multipliers` 同时存储倍率和 RPM 覆盖。本次重构：

- 删除或废弃其中 `rate_multiplier` 的读取、写入、缓存、管理端接口和用户端展示。
- 保留 `rpm_override`，并将相关接口、类型和命名收敛为 RPM 专属配置。
- 不再在余额或订阅成本计算中查询用户专属倍率。

## 迁移策略

采用多阶段兼容迁移，不直接删除旧字段：

1. 新增 `billing_profiles`，扩展现有 `subscription_plans` 和 `user_subscriptions` 快照字段及索引。
2. 为每个现有 `Group` 创建一条 `BillingProfile`，复制当前余额与通用价格配置。
3. 为尚无对应套餐的旧订阅类型分组创建一个 `SubscriptionPlan`，复制额度、有效期和套餐倍率；已有支付套餐则补齐新字段。
4. 将现有 `UserSubscription` 关联到对应套餐模板，并写入条款快照。
5. 新代码优先读取新模型；旧字段仅作为迁移期回退。新建和编辑流程只写新模型。
6. 经过至少一个发布周期、完成数据核对后，再删除 `Group` 的旧收费字段及订阅类型字段。

不能自动合并多个旧分组，即使它们账号列表相同；系统无法安全判断它们是否应共享一个新的账号分组。迁移会保留现有行为，管理员可在后续管理界面中明确合并或重新绑定套餐。

## 兼容性

- `APIKey.group_id`、`group_ids` 和 API Key 选择分组的交互保持兼容。
- 路由、端点能力、账号调度与余额回退继续以账号分组为边界。
- 旧订阅 API、管理端 DTO 和缓存快照在迁移阶段使用适配层兼容；新 API 增加套餐模板和套餐实例信息。
- 缓存版本必须递增，避免旧进程将旧 `Group` 收费字段当作有效的新计费配置。

## 错误处理

- 套餐不存在、已停用、已过期或额度耗尽：继续选择下一条订阅，非最后一条时不直接返回错误。
- 所有订阅不可用且余额充足：自动进入余额计费。
- 所有订阅不可用且余额不足：返回余额不足。
- 计费规则缺失：拒绝该分组的可计费请求并记录配置错误，不能静默按 `1.0` 计费。
- 迁移期旧数据无法映射套餐：保留旧读取路径并记录告警，禁止丢失既有用户权益。

## 验证范围

- 数据迁移：旧标准分组、旧订阅分组、已有订阅、软删除记录和重复同分组订阅。
- 调度：多个套餐、同套餐多次发放、最早到期优先、额度耗尽切换、订阅到余额回退、跨分组订阅优先。
- 计费：余额倍率、套餐倍率覆盖、图片/视频/高峰价格、账户成本倍率、零倍率与精度。
- 并发与缓存：额度恰好耗尽、并发扣费、跨实例订阅缓存失效、窗口重置。
- 接口与 UI：API Key 分组多选、套餐发放/调整、管理员配置、订阅卡、使用记录归属。
- 回归：OpenAI `chat/completions`、`responses`、其他平台端点与现有多套餐回退逻辑。

## 非目标

- 不改变账号调度算法或账号级上游成本倍率。
- 不再支持用户专属余额倍率。
- 本阶段不自动推断或合并历史账号分组。
