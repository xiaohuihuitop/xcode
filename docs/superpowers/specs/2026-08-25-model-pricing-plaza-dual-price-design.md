# 模型价格与模型广场双价格设计

## 背景

当前模型广场已经通过 `ModelPricingResolver` 读取管理员价格覆盖和默认模型价格，实际计费也使用同一解析器。但是现有产品界面没有说明价格来源，也没有区分官方公开价、平台售价和用户最终扣费价。

管理员“模型价格”页面目前只列出 `model_pricing_overrides` 中的覆盖规则，因此即使模型广场已经展示默认价格，该页面仍可能显示“暂无价格规则”。编辑表单直接要求填写每 Token 的美元价格，并暴露 `Intervals JSON`，容易造成单位错误和无效配置。

## 目标

- 模型广场同时展示官方公开价和倍率前平台售价。
- 管理员价格页面同时展示官方公开价、真实来源、平台售价和价差。
- 管理员只能编辑平台售价，不能修改价格目录中的官方公开价。
- 用户最终扣费保持为“平台售价乘套餐倍率”，并继续支持服务等级和长上下文等现有计费策略。
- 模型广场、管理员页面和实际计费使用同一套价格解析结果。
- 保留现有价格覆盖数据和旧接口兼容，不增加数据库迁移。
- 价格数据异常时禁止静默按零成本放行。

## 非目标

- 不建立采购成本、发票或财务利润核算系统。
- 不将官方价格目录复制到数据库。
- 不在本次设计中增加全局加价倍率或自动利润率策略。
- 不改变套餐倍率、服务等级倍率和长上下文倍率的业务定义。
- 不向普通用户暴露服务器文件路径、代码位置等内部来源细节。

## 术语

### 官方公开价

模型供应商公开 API 标价的参考值。该价格可能来自远程价格目录、本地内置目录或程序兜底，不等同于包月账号、订阅账号或协议账号的真实采购成本。产品页面统一使用“官方公开价（参考成本）”这一名称。

### 平台售价

管理员针对平台模型配置的倍率前基础售价。没有管理员覆盖时，平台售价继承官方公开价；部分字段覆盖时，未覆盖字段继承官方公开价。

### 用户最终扣费价

在平台售价基础上应用用户命中的套餐倍率以及请求自身的服务等级、长上下文等既有计费策略后的价格。基础关系为：

```text
用户最终扣费 = 平台售价 × 套餐倍率
```

服务等级和长上下文调整继续由现有计费策略执行，不纳入管理员平台售价输入值。

## 选定方案

采用“只读官方目录 + 数据库售价覆盖 + 统一有效价格视图”。

- 官方公开价继续由现有 `PricingService` 和 `BillingService` 提供。
- 平台售价继续存储在现有 `model_pricing_overrides` 表中。
- 新增统一的平台价格视图服务，聚合平台模型、官方价来源、命中售价规则和最终有效平台售价。
- 管理员价格页面和模型广场读取统一价格视图。
- 实际计费继续通过同一解析器获得平台售价，避免展示价格与扣费价格分叉。

不采用将官方目录复制到数据库的方案，因为该方案会引入同步冲突、过期数据和来源不明确问题。暂不采用全局加价倍率方案，因为当前需求可以通过逐模型售价覆盖满足，引入额外规则会增加解释成本。

## 数据语义

每个平台模型生成一条统一价格视图：

```text
平台 + 对外模型
├── 官方公开价
│   ├── 价格字段
│   ├── 命中的官方模型名
│   ├── 来源类型
│   ├── 来源名称或地址
│   └── 更新时间
├── 平台售价
│   ├── 命中的管理员规则
│   ├── 管理员覆盖字段
│   └── 继承的官方字段
└── 用户最终扣费
    └── 平台售价 × 套餐倍率及既有计费策略
```

Token 价格在后端和接口中继续使用 USD/Token，避免改变计费内部精度和既有接口语义。前端展示和编辑统一转换为 USD/1M Token。按次和图片价格使用 USD/次、USD/张等各自单位，不执行百万倍转换。

`null` 和显式 `0` 必须保持不同语义：

- `null`：该字段继承官方公开价。
- `0`：该字段的平台售价明确为零。

## 规则匹配

售价规则继续使用现有单规则命中语义，顺序为：

1. 平台编码 + 对外精确模型。
2. 平台编码 + 对外模型通配符。
3. 平台编码 + 上游精确模型或通配符。
4. 账号适配器 + 对外精确模型或通配符。
5. 账号适配器 + 上游精确模型或通配符。
6. 官方公开价。

同一身份内，精确模型优先于通配符，更具体的通配符优先。禁用规则不参与匹配。

命中一个管理员规则后不继续叠加其他管理员规则。该规则中为空的字段直接继承官方公开价。这样保留当前可解释的单规则行为，避免多层规则叠加造成售价不可追溯。

管理员日常编辑以“平台编码 + 对外模型”为主，例如 `codex / gpt-5.6-sol`。现有 `openai` 等账号适配器规则继续作为跨平台兼容规则，并放在高级规则区域管理。

## 官方价格来源

价格查询结果除价格外，还必须携带以下来源元数据：

```text
source_type
source_name
source_url
matched_model
updated_at
```

来源类型固定为：

- `remote_catalog`：本次进程从远程镜像成功下载的目录。
- `cached_remote_catalog`：从本地 `data/model_pricing.json` 加载的远程目录缓存。
- `bundled_catalog`：项目附带的价格目录。
- `code_fallback`：`BillingService` 中的程序兜底价格。
- `unavailable`：所有价格源均未找到该模型。

加载主价格文件时，为主文件中的模型记录主来源；合并本地内置目录时，只将内置目录独有模型标记为 `bundled_catalog`。如果本地缓存文件内容哈希与内置目录一致，则将其识别为 `bundled_catalog`，避免将曾经复制到数据目录的内置文件错误标记为远程缓存。

程序兜底必须明确标记为 `code_fallback`，不能继续笼统标记为 LiteLLM。来源元数据中的更新时间允许为空；程序兜底在管理员页面显示当前构建版本，不伪造更新时间。

普通用户模型广场只展示“官方公开价”和“平台售价”，不展示本地路径和程序内部来源。详细来源仅在管理员页面显示。

## 服务边界

### 基础价格查询

扩展价格查询能力，使其返回价格、匹配模型和来源元数据。保留现有只返回 `ModelPricing` 的方法作为兼容入口，新增带元数据的内部查询结果，供统一价格视图和解析器使用。

### 售价规则目录

现有 `ModelPricingCatalog` 继续负责管理员覆盖规则的验证、持久化和最具体规则选择。新增批量加载或请求级规则快照能力，避免模型广场逐模型重复查询数据库。

### 统一平台价格视图

新增统一价格视图服务，输入平台编码、账号适配器、对外模型和上游模型，输出：

- 官方公开价及来源。
- 命中的管理员规则及规则来源。
- 合并后的平台售价。
- 计费模式和区间价格。
- 售价状态：`official`、`custom` 或 `unavailable`。

管理员页面和模型广场都使用该服务。实际计费继续由 `ModelPricingResolver` 执行，但其官方价和规则匹配必须复用同一底层查询，不能维护另一份优先级。

## 管理员接口

保留现有 `/api/v1/admin/model-pricing` 列表和 CRUD 接口，兼容高级规则与已有前端调用。

新增平台价格目录接口：

```http
GET /api/v1/admin/model-pricing/catalog
```

支持按平台和模型关键字过滤。每行返回平台、对外模型、上游模型、计费模式、官方价格、官方来源、有效平台售价、命中规则和售价状态。

新增平台模型售价 Upsert 接口：

```http
PUT /api/v1/admin/model-pricing/platform-sale
```

请求包含平台 ID、对外模型、计费模式、可空价格字段、结构化区间和状态。后端根据平台编码与模型创建或更新精确规则，不允许前端提交任意未注册平台作为普通编辑目标。

恢复继承时优先删除精确规则，使价格回到下一条有效规则或官方价。如果管理员明确要求绕过现有通配规则并直接使用官方价，则保留一条全部价格字段为空的精确启用规则，利用单规则命中语义屏蔽通配规则。

所有售价修改记录管理员审计信息，包括平台、模型、修改前规则、修改后规则和操作人。

## 模型广场接口

`GET /api/v1/model-plaza` 采用加法兼容扩展：

- 保留现有 `pricing` 字段，语义继续为倍率前有效平台售价。
- 新增 `official_pricing`，表示官方公开价。
- 新增 `sale_pricing`，与新前端使用的有效平台售价一致。
- 新增 `sale_pricing_source`，表示继承官方价或管理员自定义规则。

旧前端继续读取 `pricing`，新前端读取双价格字段。接口不返回管理员身份、数据库内部信息或服务器文件路径。

## 管理员页面

管理员“模型价格”页面以活动平台中的启用模型为主列表，不再以覆盖表物理行作为唯一内容来源。

主列表字段包括：

- 平台。
- 对外模型和上游模型。
- 计费模式。
- 官方公开价。
- 平台售价。
- 价差比例。
- 售价状态。
- 编辑操作。

展开行显示缓存、图片、按次和区间价格，以及官方来源、匹配模型、同步时间和命中售价规则。

编辑器采用官方价只读、平台售价可编辑的左右对照形式。每个售价字段使用明确的“继承官方价”控制和数值输入，显式零价格不得通过清空输入框表达。

Token 输入统一显示 USD/1M Token，保存时转换为 USD/Token。按次和图片字段显示各自单位。编辑器实时预览最终有效平台售价和相对官方价的价差。

现有 `Intervals JSON` 替换为结构化区间编辑器，支持新增、删除、排序和上下界校验。通配符和账号适配器规则保留在“高级规则”区域。

## 模型广场页面

每个平台模型同时展示官方公开价和平台售价，两列均按计费模式使用正确单位。平台售价等于官方价时仍展示两列，并标记为继承官方价。

Token 模式展示输入、输出、缓存读写和适用区间；按次模式展示每次价格和层级；图片模式展示图片输入、输出或每张价格。明确零价格显示 `$0`，缺失价格显示“暂无价格”，两者不能都显示为 `-`。

模型广场展示倍率前平台售价。不同用户套餐的最终价格不在公共页面展开，继续由套餐倍率在实际请求计费时计算。

## 异常处理

- 远程目录同步失败时继续使用缓存或内置目录，并返回真实来源。
- 官方价格找不到时返回 `unavailable`，不能构造零价格。
- 平台规则提供完整售价时，官方价格缺失不阻止按完整售价计费。
- 平台规则依赖官方字段但官方价格缺失时，实际计费失败关闭，不写入零成本成功用量。
- 售价规则数据库读取失败时，实际计费失败关闭，不能静默退回官方价。
- 管理员目录接口在无法确定有效售价时返回明确错误状态，不伪造售价。
- 负数、非数字、溢出价格、无效计费模式、区间重叠和无效上下界在保存前拒绝。
- 官方目录更新不覆盖管理员售价；未覆盖字段在下次查询时自动继承新官方价。

## 兼容性

- 不修改 `model_pricing_overrides` 表结构。
- 不迁移或重写现有价格覆盖记录。
- 保留现有管理员价格 CRUD。
- 保留模型广场现有 `pricing` 字段。
- 保留现有平台编码和账号适配器规则优先级。
- 不改变套餐倍率、服务等级和长上下文计费公式。

## 验证

### 后端单元测试

- 远程目录、远程缓存、内置目录、程序兜底和不可用来源识别。
- 官方价格查询返回命中的真实模型名。
- 平台精确、平台通配符、适配器精确和适配器通配符优先级。
- 单规则命中后空字段继承官方价。
- 显式零价格与空值保持区别。
- 官方价缺失但完整售价存在时可计费。
- 官方价缺失且售价依赖继承时失败关闭。
- 规则仓库错误时实际计费失败关闭。
- 最终扣费等于平台售价乘套餐倍率，并保留现有服务等级和长上下文行为。
- 区间重叠、非法边界和负数价格被拒绝。

### 后端接口测试

- 管理员目录返回官方价、来源、平台售价和命中规则。
- 平台售价 Upsert 创建和更新正确的精确规则。
- 普通用户不能调用管理员价格接口。
- 模型广场返回兼容 `pricing` 和新增双价格字段。
- 公共接口不泄露内部路径或管理员审计信息。

### 前端测试

- 管理员列表同时显示官方价和平台售价。
- USD/1M Token 与 USD/Token 双向转换无精度错误。
- 继承、显式零和自定义价格三种状态正确提交。
- 结构化区间编辑器拒绝无效区间。
- 模型广场正确展示 Token、按次、图片和区间价格。
- `$0` 与“暂无价格”显示不同。
- 桌面和移动视口不存在表格溢出、文本重叠或操作遮挡。

### 集成验收

- 使用真实平台模型调用后，模型广场平台售价、usage 记录成本和订阅扣费一致。
- 修改一个平台售价后，不影响其他平台同名模型。
- 删除精确售价后恢复正确继承结果。
- 官方目录更新后，自定义字段保持不变，继承字段随官方价更新。

## 上线

本功能不需要数据库迁移。发布前完成后端定向测试和完整单元测试、前端测试、类型检查、生产构建、后端构建和差异检查。

部署后先只读核对管理员价格目录和模型广场，再使用临时 API Key 执行真实请求，确认展示售价、usage 成本和套餐扣费一致。临时 Key 验收后删除，usage 审计记录按现有规则保留。现有生产镜像保留为回滚目标。

## 验收标准

- 管理员能够在一个页面查看每个活动平台模型的官方公开价、来源和平台售价。
- 管理员使用 USD/1M Token 编辑平台售价，不需要填写每 Token 科学计数法。
- 模型广场同时展示官方公开价和平台售价。
- 页面显示的平台售价与实际计费使用同一解析结果。
- 用户最终扣费继续等于平台售价乘套餐倍率及既有请求级策略。
- 官方价缺失、规则读取失败或售价不完整时不会产生静默零成本请求。
- 现有价格覆盖、旧模型广场字段和生产数据无需迁移即可继续使用。
