# 模型价格、API Key 与充值页 UI 调整设计

## 目标

在不新增数据库结构、不改变现有计费内核互斥语义的前提下，完成模型广场、管理员模型价格、API Key 和充值页面的五项界面调整。

## 已确认行为

### 模型广场

- 移除“自定义售价”提示，避免价格区列宽和基线错位。
- 平台售价与官方公开价不一致时，只将发生变化的售价数字标红。
- 不区分价格上涨或下降，不展示价差方向文字。
- 官方价缺失、计费模式不同或对应价格字段不可比较时，不做红色标记。

### 图片计费模式

- 管理员平台售价继续使用现有 `Token`、`按次`、`图片` 三种互斥模式。
- 图片模型可切换为“图片”模式并填写每张图片价格。
- 图片模式与 Token 模式不叠加；运行时继续按照已解析的单一 `billing_mode` 计费。
- 本次不新增 schema、migration 或新的计费字段，仅改善管理员界面中的模式选择与“每张图片”表达，并补充回归测试。

### API Key 页面端点

- API Key 页面顶部始终显示 API 端点和复制按钮。
- 后台配置 `api_base_url` 时优先使用该地址。
- 后台未配置时，默认使用当前站点 `window.location.origin` 并规范化为 `/v1` 端点。
- 自定义端点继续保留在现有端点弹层中。

### 充值页面

- 自定义金额标题改为“自定义支付金额”，其中“支付”使用语义危险色强调；英文保持自然完整文案，不拆词着色。
- 金额输入前缀随当前支付方式币种变化；CNY 显示 `¥`，USD 显示 `$`，其他币种使用现有货币格式能力得到适合的符号或代码。
- “支付金额”、手续费与实付金额继续使用当前支付方式币种。
- “到账额度”继续用 `$` 表示美元额度，明确区分支付货币与到账额度。
- 输入区下方展示后台支付设置的最小充值额度和最大充值额度；`0` 表示不限制，并使用当前支付方式币种格式化。
- 后台充值上下限来自现有 `/payment/config` 的 `min_amount` 与 `max_amount`，不修改 `checkout-info` 公共响应结构。
- 前端可提交条件同时满足后台充值上下限和所选支付渠道的单笔上下限；服务端现有校验继续作为最终边界。

## 数据流与边界

- 模型广场只比较当前行中官方价格和平台售价对应字段，不向普通用户暴露来源路径或管理员规则。
- 管理员价格编辑继续通过现有 `upsertPlatformSale` 保存，图片模式使用现有 `per_request_price` 表示每张图片价格。
- API Key 默认端点只在前端根据当前 origin 生成，不写回设置。
- 充值页并行读取现有 checkout 信息和支付配置；配置读取失败时沿用现有页面错误处理，不伪造上下限。

## 可访问性与响应式

- 金额输入保留可见标签，并将上下限作为辅助文本与输入控件关联。
- 红色只用于表示售价已修改，同时价格差异仍可通过官方价与平台售价数值比较，不把颜色作为唯一信息来源。
- 端点复制按钮继续使用现有键盘、焦点和复制反馈实现。
- 新增文本允许换行，移动端不引入固定宽度或横向滚动。

## 测试与验收

- 组件测试覆盖：移除售价标签、差异售价标红、相同售价不标红、跨模式不标红。
- 管理员价格测试覆盖：图片模式选择、每张图片价格输入和保存 payload。
- API Key 测试覆盖：空后台配置时显示当前站点 `/v1`，后台配置优先，自定义端点保留。
- 充值测试覆盖：CNY/美元符号、标题强调、上下限显示、无限制显示及业务上下限参与提交校验。
- 运行定向 Vitest、完整前端测试、类型检查、lint 和生产构建；最后在桌面与移动视口做视觉检查。
