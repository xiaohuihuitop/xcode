# 平台安全删除与订阅购买文案设计

- 状态：已确认，待实施计划
- 日期：2026-08-12
- 目标分支：`my2.0`

## 背景

当前平台管理页只能新增和编辑平台，无法删除误建或完全未使用的平台。同时，管理端“订阅套餐”和用户购买页的“续费”文案与实际业务语义不一致：每次购买都会创建一条新的独立订阅实例，并不会延长已有订阅的有效期。

本次调整补齐平台安全删除能力，并让管理端和购买端文案准确表达当前订阅模型。订阅发放、计费、套餐选择和多订阅调度逻辑保持不变。

## 目标

1. 管理员可以删除完全未使用的平台。
2. 被任何业务或历史数据引用的平台不得删除，且界面明确说明阻止原因。
3. 管理端销售模板入口统一显示为“上架订阅”。
4. 用户购买相同套餐时显示“再来一个”，不再显示“续费”。
5. 购买页明确说明每次购买都会新增独立订阅，多个订阅不会合并有效期。

## 非目标

- 不提供强制删除平台。
- 不自动解绑账号或 API Key。
- 不清空使用记录、审计记录或运维记录中的平台归属。
- 不改变购买后创建独立 `UserSubscription` 的现有后端行为。
- 不全局替换“订阅套餐”这一领域术语；API Key 授权、用户订阅实例和使用记录等位置继续使用原有准确名称。
- 不新增数据库字段或迁移。

## 平台安全删除

### API

新增管理员接口：

```http
DELETE /admin/platforms/:id
```

删除成功使用项目统一成功响应。平台不存在时沿用 `PLATFORM_NOT_FOUND`；平台仍被引用时返回 HTTP 409 和错误码 `PLATFORM_IN_USE`。

接口不接受 `force`、级联解绑或忽略历史引用等参数。

### 删除条件

只有完全未使用的平台允许物理删除。删除前必须检查当前 schema 中所有保存业务平台 ID 的表，至少包括以下类别：

- 账号归属；
- API Key 平台授权；
- 使用记录与计费归属；
- 内容审核、提示词审计及其他审计记录；
- 调度事件、运维错误、指标和告警等运行记录。

只要任一类别存在引用，删除必须失败。响应应包含可供管理员理解的阻止原因；前端直接展示后端返回的安全错误信息，不进行自动清理。

平台自身的模型规则不属于外部引用。平台满足删除条件后，允许在同一事务中删除它及其 `platform_model_rules`。

### 事务与并发

Repository 在单个数据库事务中完成以下操作：

1. 锁定目标平台并确认其存在；
2. 检查所有当前引用；
3. 存在引用时回滚并返回 `PLATFORM_IN_USE`；
4. 无引用时删除平台，由既有外键级联删除平台模型规则；
5. 提交后后续平台路由和模型列表读取自然反映删除结果。当前实现每次从持久化的 `platforms` / `platform_model_rules` 读取，不新增并不存在的平台目录缓存或失效接口。

不得依赖数据库当前的 `ON DELETE SET NULL` 作为删除策略，因为这会丢失历史数据的平台归属。

### 管理界面

平台列表的操作列增加删除图标按钮，并提供名称明确的悬浮提示。点击后显示确认对话框，确认文案包含平台名称，并说明只有未使用的平台才能删除。

删除成功后刷新列表并显示成功提示。删除被阻止时保留平台数据，显示后端返回的引用原因。界面不提供强制删除入口。

## 用户购买页

### 按钮文案

- 用户没有同一套餐的有效订阅：显示“立即开通”。
- 用户已有同一套餐的有效订阅：显示“再来一个”。

前端状态命名同步从“续费”改为“已有同套餐有效订阅”，避免代码继续表达不存在的续期语义。

### 业务提示

套餐列表上方固定显示：

> 每次购买都会新增一个独立订阅，不会延长已有订阅的有效期；多个订阅可同时存在，并按系统规则依次使用。

付款确认区域再次显示同一语义，确保用户付款前能够看到。提示只说明实际购买和使用规则，不暗示多个套餐会同时扣费。

### 后端行为

购买、支付回调和 CDK 发放继续为每次成功发放创建一条新的独立订阅实例。既有同套餐订阅的开始时间、到期时间和额度不变，新订阅拥有自己的有效期、额度窗口和倍率快照。

## 错误处理

- 平台 ID 无效：返回项目统一参数错误。
- 平台不存在：返回 `PLATFORM_NOT_FOUND`。
- 平台存在引用：返回 HTTP 409 `PLATFORM_IN_USE`，不修改任何数据。
- 删除事务失败：返回统一内部错误，并记录可追踪日志；不得返回成功。
- 前端删除请求失败：保留当前列表，展示具体错误，不静默忽略。

## 验证范围

### 后端

- 删除完全未使用的平台成功，并清理其模型规则。
- 账号引用时阻止删除。
- API Key 授权引用时阻止删除。
- 使用记录、审计或运维记录引用时阻止删除。
- 平台不存在、非法 ID 和事务失败返回正确错误。
- 删除失败时平台及模型规则均保持不变。
- 管理员路由权限和响应格式回归。

### 前端

- 平台列表显示删除按钮和确认对话框。
- 删除成功后刷新列表；`PLATFORM_IN_USE` 时显示阻止原因。
- 管理端导航、标题和描述显示“上架订阅”。
- 无同套餐有效订阅时显示“立即开通”。
- 有同套餐有效订阅时显示“再来一个”。
- 套餐列表与付款确认区域均显示独立订阅提示。
- 中文和英文翻译键完整。

### 工程检查

- 运行相关后端 repository、service 和 handler 单元测试。
- 运行相关前端 Vitest。
- 运行前端 typecheck、lint 和生产构建。

## 风险与约束

- 平台 ID 分布在业务、审计和运维表中，实施前必须对当前 schema 做一次完整扫描，不能只检查有外键的表。
- 新增引用表时必须同步扩展平台删除引用检查；该约束应记录到项目记忆。
- 当前数据库部分外键允许删除平台后将引用设为空，本功能必须始终通过受控 Service/Repository 路径执行，不能直接依赖外键行为。
- 本次只修改展示文案，不修正或扩展在线支付、退款和订单快照等其他上线风险。
