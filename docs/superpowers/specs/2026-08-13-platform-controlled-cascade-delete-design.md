# 平台受控级联删除设计

## 背景与目标

当前平台删除会把账号、API Key、使用记录、审计记录、运维记录和平台范围配置全部视为阻断引用。旧平台通常已经没有账号和 API Key，但仍保留大量历史记录，管理员无法从平台页面完成清理。

本次将删除语义改为“受控级联删除”：账号或 API Key 仍然阻止删除；仅有历史、审计、运维和平台范围配置引用时，由系统在同一事务中清理这些引用并删除平台。

## 已确认规则

- 账号引用数大于零时，拒绝删除并返回 `PLATFORM_IN_USE`。
- API Key 引用数大于零时，拒绝删除并返回 `PLATFORM_IN_USE`。
- 使用记录、Prompt Audit、内容审核、调度 Outbox、运维错误、运维聚合、告警事件和告警规则不阻止删除，随平台自动清理。
- 内容审核与 Prompt Audit 的全局设置不能整行删除；只从对应 `platform_ids` 数组移除目标平台 ID。
- 平台模型规则继续随平台删除。
- 不删除用户、余额、订阅、订单、CDK、账号或 API Key，不修改其他平台的数据。
- 清理引用与删除平台必须在同一个 PostgreSQL 事务中执行；任一步失败时全部回滚。
- 不提供绕过账号/API Key 检查的“强制删除”参数。

## 接口与交互

新增管理员只读接口 `GET /api/v1/admin/platforms/:id/delete-impact`，返回：

- `accounts`、`api_keys`：阻断数量。
- `usage_logs`、`audits`、`ops`、`configs`：删除时将自动清理的数量。
- `can_delete`：仅当账号与 API Key 均为零时为 `true`。

平台页点击删除后先获取影响预览。确认框明确说明：

- 有账号或 API Key 时不可删除，并展示阻断数量。
- 可删除时展示将永久清理的使用、审计、运维和配置数量。
- 用户确认后调用现有 `DELETE /api/v1/admin/platforms/:id`。

若预览后新建了账号或 API Key，删除事务会重新计数并拒绝删除，不能依赖旧预览放行。

## 后端事务

删除事务按以下顺序执行：

1. `SELECT ... FOR UPDATE` 锁定目标平台。
2. 锁定会写入平台引用的相关表，并重新统计全部引用。
3. 若账号或 API Key 非零，返回带计数元数据的 `PLATFORM_IN_USE`。
4. 删除或清理历史引用。存在父子关系时先删除子表，例如先删 Prompt Audit 事件再删任务、先删告警事件再删告警规则。
5. 对可选表 `ops_alert_silences` 继续使用 `to_regclass` 探测；表存在才清理，不存在不报错。
6. 更新平台范围设置，只移除目标平台 ID；保留设置中的其他字段和其他平台 ID。
7. 删除平台。平台模型规则由现有关系处理或在事务中显式删除。
8. 提交事务。

所有 SQL 使用参数化查询。任何未纳入清理清单的新平台引用或外键错误都应导致事务回滚并返回错误，不允许静默忽略。

## 并发与错误语义

- 删除预览只用于提示，最终安全判断始终在删除事务中完成。
- 账号/API Key 引用返回 `409 PLATFORM_IN_USE`，前端显示实际阻断计数。
- 平台不存在返回 `404 PLATFORM_NOT_FOUND`。
- 清理或提交失败返回服务错误，平台及历史记录均保持原状。
- 成功删除返回清理统计，供前端成功提示或审计使用。

## 验证

- Repository 测试：无引用删除、账号阻断、API Key 阻断、仅历史引用时清理成功、可选表缺失、清理中途失败回滚、设置 JSON 只移除目标 ID。
- Service/Handler/Route 测试：影响预览、409 元数据和删除成功响应。
- 前端测试：预览加载、阻断状态、历史数量提示、确认删除、接口失败。
- 完整门禁：后端 unit/integration、前端 Vitest/typecheck/lint/build、`git diff --check`。
- 生产部署前备份 PostgreSQL；部署后先对一个无账号、无密钥的旧平台验证，并核对其他平台、用户资产和当前平台记录未变化。

## 非目标

- 不增加全库清空功能。
- 不增加批量删除平台。
- 不提供恢复已清理历史的应用内功能；恢复只能使用部署前数据库备份。
- 不改变订阅、余额或计费逻辑。
