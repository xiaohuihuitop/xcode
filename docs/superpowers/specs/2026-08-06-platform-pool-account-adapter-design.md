# 平台唯一入口与账号适配器派生设计

- 状态：已确认，待编写实施计划
- 日期：2026-08-06
- 目标分支：`my2.0`
- 兼容策略：不兼容旧路由配置，不迁移旧平台、账号分组或 API Key 平台授权

## 目标

平台是管理员和 API Key 唯一可见的路由概念。一个平台拥有协议适配器、模型规则、端点能力和账号集合；账号只加入一个平台，不再单独选择“账号平台”或旧分组。

套餐和余额继续作为跨平台用户资产。Sub2API 的账号调度、OAuth 刷新、协议转换、上游失败切换和模型基础计价继续保留，不以本次重构名义重写。

## 术语与职责

| 概念 | 负责 | 不负责 |
| --- | --- | --- |
| `Platform` | 业务平台、模型规则、端点能力、账号集合 | 套餐额度、余额倍率、用户扣费授权 |
| `Adapter` | OAuth、凭证类型、协议转换、上游请求实现 | 业务平台命名、API Key 权限、资产选择 |
| `Account` | 凭证、账号状态、并发、调度参数 | 套餐、余额、模型价格 |
| `SubscriptionPlan` / `UserSubscription` | 时长、日/周/月额度、套餐倍率与实例用量 | 平台和账号调度 |
| `Balance` | 用户余额与全局余额倍率 | 套餐倍率、平台配置 |
| `PricingCatalog` | 按模型计算未乘资产倍率的基础费用 | 决定扣套餐还是余额 |

## 核心领域模型

### Platform

- 一条 `Platform` 记录表示一个业务平台，例如 `openai`、`glm` 或 `codex`。
- 平台保存名称、编码、启停状态和协议适配器；模型规则保存客户端模型模式、上游模型映射和端点能力。
- 平台与账号是一对多关系，账号只通过 `platform_id` 归属一个平台。
- 协议适配器只允许 `openai`、`anthropic`、`gemini`、`grok`、`antigravity`。
- 当前数据库字段 `platforms.account_platform` 继续作为适配器字段使用，但 UI 统一显示为“协议适配器”。
- 平台已经拥有未删除账号后，协议适配器不可修改；需要更换协议时创建新平台并重新添加或授权账号。

### Account

- 创建和编辑请求中的平台归属字段只有 `platform_id`；名称、认证类型、凭证、代理和调度参数仍按对应账号流程提交。
- 服务端先加载平台，再使用平台适配器选择凭证表单、OAuth、令牌刷新、协议转换和上游请求实现。
- 当前 `accounts.platform` 和 `service.Account.Platform` 被大量 GatewayRuntime 逻辑使用，本阶段保留为服务端派生的适配器快照：客户端不可编辑，创建、复制、OAuth、导入及移动账号时必须由 `Platform` 覆盖写入。
- `accounts.platform` 不是第二个配置来源。读取账号时若它与所属平台适配器不一致，账号禁止调度并报告配置错误，不能静默猜测。
- 账号可以在使用相同适配器的平台之间移动。跨适配器移动必须重新创建或重新授权，防止凭证和账号类型被错误复用。
- Spark shadow 账号继承父账号的 `platform_id` 和派生适配器，不能独立选择或移动平台。

### ModelRule 与端点能力

- 模型规则属于平台，支持精确模型名或单个后缀通配符，例如 `gpt-5`、`gpt-*`。
- 每条启用规则必须显式勾选至少一个端点能力；空数组不再解释为“支持全部端点”。
- 端点能力使用服务端统一枚举，至少覆盖当前公开入口；OpenAI 兼容入口必须区分 `chat_completions` 与 `responses`。
- 同一模型模式可以存在于多个平台。合法场景包括不同 API Key 分别授权不同平台，或同一模型的 Chat 与 Responses 分别由不同平台处理。
- 精确规则优先于通配符；通配符按前缀更长者优先。经过授权和端点过滤后，同一最高优先级仍有多个平台时返回歧义错误。

### API Key 与资产

- API Key 必须授权至少一个平台，可以授权多个平台；套餐可以多选或不选，余额开关独立，创建 Key 时余额默认勾选。
- 套餐、余额和平台三组选择必须在一次更新中同时保存，不能互相覆盖。
- 请求只允许使用 Key 显式授权的平台、套餐和余额；没有平台授权的 Key 直接拒绝，不进入旧 Group 路径。
- 套餐按最早到期、再创建时间选择可用实例；所有授权套餐均不可用后，只有 Key 允许余额且余额充足时才回退余额。
- 套餐倍率取订阅实例快照，余额倍率取全局设置，两者绝不叠乘。

## 请求解析顺序

新请求必须按以下顺序产生唯一调度结果：

1. 根据客户端模型查找所有启用的匹配规则，不提前选定单个平台。
2. 只保留 API Key 已授权的平台。
3. 只保留支持当前标准化端点能力的平台规则。
4. 按“精确优先、通配符前缀更长优先”保留最高优先级候选。
5. 候选为零时返回无可用平台或端点不支持；候选多于一个时返回平台歧义错误。
6. 在唯一平台的账号集合中调用既有 GatewayRuntime 调度、OAuth 刷新和失败切换。
7. 独立选择套餐或余额，计算基础模型费用并乘本次资产倍率，最后记录实际平台、账号和资产归属。

`ProductCore.PlatformCatalog` 因此不能继续只提供 `ResolveModel(model) -> Platform`。实施时应改为返回模型候选集合，由 `ProductCore.Authorizer` 结合 Key 授权和端点能力完成唯一性判断；平台目录不能读取 API Key 权限。

### 配置冲突检查

- 保存 API Key 时，检查它授权的平台对现有模型和端点是否存在同优先级歧义；发现冲突时拒绝保存并列出平台、模型模式和端点。
- 保存平台或模型规则时，检查受影响的现有 API Key；若会使已生效 Key 产生歧义则拒绝保存。
- 运行时仍保留歧义错误，防止并发配置更新或异常数据绕过管理端校验。

## 模型定价边界

- GatewayRuntime 继续按最终上游模型计算基础费用，ProductCore 只决定本次使用的套餐或余额倍率。
- 热门模型继续使用 Sub2API 的默认价格；管理员仍可为缺失模型添加自定义价格。
- 新自定义价格属于独立 `PricingCatalog`，按“适配器、上游模型、计费模式、规格/层级”匹配，不属于 Platform、套餐、余额或 API Key。
- 当前 `Platform.legacy_group_id`、`PricingGroupID` 及 Group 媒体价格不能继续成为新请求的定价入口。实施时必须把相关调用改为显式模型定价上下文，再从新平台管理表单移除 `legacy_group_id`。
- 旧 Group 自定义价格不自动迁移；切换前由管理员在新定价目录重新录入需要保留的自定义价格。
- `Account.rate_multiplier` 只用于上游成本或账号统计，不参与用户套餐/余额扣费倍率。

## 用户界面

### 平台管理

- 菜单、页面标题、API Key 授权和账号列表统一使用“平台”，不再显示“平台账号池”。
- 平台编辑页显示协议适配器、模型规则、上游模型和端点能力；平台存在账号后适配器只读。
- GLM 使用 OpenAI 兼容协议时创建独立 `glm` 平台并选择 `openai` 适配器；用模型规则与 OpenAI 平台区分。
- 平台管理页不显示套餐、余额倍率、Group 或旧定价分组字段。

### 账号管理

- 创建账号第一项只选择“所属平台”。选择后显示只读协议提示，并渲染对应的 OAuth、API Key 或其他凭证表单。
- 不显示可编辑的第二个平台控件，不显示旧分组控件。
- 编辑账号时，所属平台下拉只显示相同适配器的平台；跨适配器变更提示重新创建账号。
- 账号列表以“所属平台”为主要列；“适配器/认证”仅作为只读技术信息。
- 没有启用平台时禁用账号提交，并提示先创建平台。

### API Key

- 创建和编辑弹窗同时显示平台、套餐和余额授权；平台至少选择一个，余额默认选中。
- 再次打开弹窗必须同时回显三组真实持久化状态。
- 详情列表只读展示已选平台和套餐，不提供容易误操作的行内下拉。

## API 与服务边界

- 普通创建、批量创建、OAuth、Refresh Token、Codex Session、Codex PAT、Grok SSO、复制和数据导入必须共用同一个平台解析服务。
- 所有外部创建请求都必须包含 `platform_id`，不得接受客户端提供的适配器覆盖平台配置。
- 更新账号平台时，目标平台必须启用且适配器与原平台一致。
- 平台停用后不参与模型解析和账号调度，但所属账号仍可编辑名称、凭证、并发、代理和状态；重新分配平台时目标平台必须启用。
- API 响应返回所属平台和只读适配器信息，前端不自行猜测适配器。
- GatewayRuntime 只接收解析后的平台、派生适配器、上游模型、端点能力和资产倍率，不读取旧 Group 决定平台或资产。

## 放弃旧配置

“不兼容旧配置”表示旧配置不再参与新请求，不等于无条件物理删除仍被审计数据引用的行。

### 重建范围

- 升级前生成并校验数据库备份。
- 旧平台和模型规则退出活动配置；重新创建平台、模型规则和端点能力。
- 旧账号软删除或归档，管理员在新平台下重新添加或重新授权账号。
- 清空所有 API Key 平台关联；Key 本体保留，但在重新勾选平台前不可请求。
- 不迁移旧 `groups`、`group_id` / `group_ids`、`account_groups`、旧平台映射、旧 API Key 平台授权或旧 Group 自定义价格。

### 保留范围

- 保留用户、API Key 本体与 Key 值、余额、套餐、订阅实例、Key 套餐授权、余额开关、支付订单、退款审计和历史使用记录。
- 保留历史记录中的实际账号、平台、订阅和费用事实；重建配置不能修改、重算或重新归属历史用量。
- 被历史用量或订单引用的旧账号、平台和 Group 数据可以只读归档，但不得进入新请求、管理选择项或运行时回退。
- 物理删除旧表或字段必须另立迁移：先完成引用清单、必要快照回填、外键处理和恢复演练。本阶段不直接删除。

### 切换顺序

1. 备份并记录关键表行数、资产总额和历史用量校验值。
2. 部署新 schema 与新 API，默认拒绝没有平台授权的 Key。
3. 归档旧路由配置，清空 Key 平台关联，创建新平台和模型定价。
4. 在新平台下重新添加账号，为 API Key 重新授权平台。
5. 验证路由、端点、套餐优先、余额回退、用量归属和模型费用后再开放测试流量。
6. 保留可恢复备份；旧管理 UI 与旧路由 API 在代码引用清零后删除。

## 错误处理

- 平台不存在或未启用：拒绝新建账号和平台重新分配。
- 平台适配器不受支持：拒绝创建或保存平台。
- 平台已有账号时修改适配器：拒绝并提示创建新平台。
- 账号派生适配器与平台不一致：禁止调度并报告数据错误。
- 账号跨适配器移动：拒绝并提示重新创建或授权账号。
- API Key 没有平台授权：返回平台未授权，不读取旧分组兜底。
- 授权平台中没有模型候选：返回模型不可用。
- 模型候选存在但都不支持端点：返回端点不支持。
- 过滤后仍有多个同优先级平台：返回平台歧义并列出冲突候选。

## 验证范围

- 平台测试：适配器枚举、已有账号时适配器不可变、端点能力必选、停用平台不参与请求。
- 路由测试：同模型不同端点选择不同平台；不同 Key 选择不同平台；同 Key 同端点歧义被拒绝；精确规则优先于通配符。
- 账号测试：所有创建入口只接收 `platform_id`；服务端覆盖派生适配器；同适配器可移动；跨适配器失败；Spark shadow 继承平台。
- API Key 测试：平台、套餐、余额一次保存且同时回显；缺少平台拒绝；套餐多选与余额默认值保持。
- 调度测试：唯一平台内多账号支持负载均衡、OAuth 刷新和失败切换，其他平台账号不会混入。
- 定价测试：默认热门模型、自定义模型、图片/视频/按次价格均不读取 Group；基础费用只乘当前资产倍率。
- 计费测试：套餐优先、耗尽后切换下一实例、全部不可用后按授权回退余额；使用记录归属实际平台、账号、订阅和倍率。
- 重建演练：备份可恢复，Key 在重新授权前拒绝请求，用户财产和历史记录校验值不变。
- 前端测试：只显示一个平台概念，账号与 Key 表单回显正确，旧 Group 控件和旧定价字段不可见。

## 不在本次范围

- 不新增 GLM 原生协议适配器；GLM 暂时按 OpenAI 兼容协议接入。
- 不重写 GatewayRuntime 的 OAuth、协议适配、调度和上游失败切换算法。
- 不改变套餐额度、套餐倍率、全局余额倍率或用量计算公式。
- 不在本阶段物理删除仍被历史记录或订单引用的旧表和字段。
