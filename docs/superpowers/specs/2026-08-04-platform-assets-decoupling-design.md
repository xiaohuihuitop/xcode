# Sub2API 平台与资产解耦设计

> **历史设计：** 本文件记录 `my2-v0.2.x` 第一阶段实现。关于“全局唯一模型平台”、旧
> Group 双读和迁移兼容的内容已被
> [平台唯一入口与账号适配器派生设计](2026-08-06-platform-pool-account-adapter-design.md)
> 替代；平台与资产解耦、套餐优先和余额回退原则继续有效。

## 状态

- 状态：已确认，进入实施
- 日期：2026-08-04
- 开发分支：`my2.0`
- 设计来源：`my2.0.drawio` 与已确认的业务规则

## 目标

将“平台账号调度”和“用户资产扣费”拆为两个独立领域：

- 平台只负责模型白名单、接口能力、账号池和调度。
- 套餐与余额都是用户资产，可用于任意已授权的平台和模型。
- API Key 分别控制可用平台与可扣费渠道。
- 保留 Sub2API 现有热门模型价格、模型自定义收费、实际扣费、并发扣费和使用记录能力。

本设计不改变模型基础价格的计算公式，只改变最终资产倍率和资产选择来源。

## 已确认规则

### 平台与账号

1. 每个系统平台有且只有一个共享账号池，例如 OpenAI、GLM、Grok。
2. 账号只属于其自身平台，不允许跨平台混用或混合调度。
3. 新建、编辑账号时不再选择套餐、余额或分组；账号由现有 `Account.platform` 直接归入对应平台池。
4. 平台维护模型白名单、端点能力、调度配置和启用状态。
5. 一个对客户端可见的模型名或模型模式只能归属一个启用平台。跨平台的精确重名、通配符重叠或映射别名冲突均禁止保存。

### 套餐与余额

1. 套餐是全局资产，不绑定任何平台。
2. 套餐只定义名称、时长、日/周/月额度和套餐倍率。
3. 用户订阅实例只绑定套餐模板，保存发放时的额度、时长和倍率快照。
4. 余额是全局资产，使用一个全局余额倍率。
5. 套餐倍率只影响使用该套餐实例的请求；余额倍率只影响使用余额的请求，两者绝不相乘。
6. 模型基础价格与自定义模型收费继续由现有 Sub2API 定价体系处理，不因本设计改变。

### API Key

1. API Key 独立保存可用平台列表。
2. API Key 独立保存可用套餐模板列表。
3. API Key 使用 `allow_balance` 控制是否允许扣用户余额；新建 Key 默认开启，管理员可关闭。
4. 新建或编辑 Key 必须至少选择一个平台，并至少选择一个扣费渠道（套餐或余额）。
5. API Key 允许选择用户当前尚未拥有的套餐模板，以便后续发放套餐后自动生效；请求时只使用该用户实际持有的有效订阅实例。

### 请求与扣费

```text
客户端模型名
  -> 解析唯一平台
  -> 验证 API Key 是否允许该平台
  -> 在该平台账号池内按现有能力与调度规则选择账号
  -> 查询该 Key 允许的用户有效订阅实例
  -> 按到期时间、创建时间选择最先消耗的套餐实例
  -> 套餐全部不可用时，若 Key 允许余额则使用余额
  -> 现有模型定价结果 x 当前资产倍率
  -> 记录实际平台、账号、资产来源、倍率和费用
```

套餐候选统一按 `expires_at ASC, created_at ASC` 排序。额度耗尽、过期、暂停或不存在的实例在本次请求中跳过；所有允许套餐均不可用后才尝试余额。

## 目标领域模型

### Platform

新增面向业务的 `Platform` 配置。每条配置对应一个现有账号平台值，例如 `openai`、`glm` 或 `grok`。

| 字段/能力 | 说明 |
| --- | --- |
| `id`、`code`、`name`、`status` | 平台身份；`code` 与 `Account.platform` 一一对应且唯一 |
| 模型白名单与映射 | 用于客户端模型名到唯一平台的解析 |
| 端点能力 | 控制 chat completions、responses、messages、Live 等可用性 |
| 调度配置 | 保留平台级现有调度、模型路由和限流能力 |
| `legacy_group_id` | 仅迁移期关联旧 `Group`，用于保留现有渠道模型定价上下文 |

新请求的账号查询只按 `Account.platform` 过滤，不再通过 `account_groups` 查询。`account_groups` 在迁移完成前只保留历史兼容，不再由账号表单写入。

### SubscriptionPlan 与 UserSubscription

`SubscriptionPlan` 不再拥有 `group_id`。它保留商品展示字段、时长、日/周/月额度和 `rate_multiplier`。

`UserSubscription` 不再以 `group_id` 作为权益归属，而以 `subscription_plan_id` 和快照字段为准。新实例必须关联套餐模板；迁移期无法映射套餐的旧实例不得进入新扣费链路，必须在预检中人工处理。

### API Key 权限

新增两张独立关系表与一个余额开关：

| 存储 | 含义 |
| --- | --- |
| `api_key_platforms` | API Key 到允许平台的多对多关系 |
| `api_key_subscription_plans` | API Key 到允许套餐模板的多对多关系 |
| `api_keys.allow_balance` | 是否允许该 Key 使用用户余额，默认 `true` |

旧 `group_id`、`group_ids` 和旧授权关系只作为迁移期读兼容来源。新 API、DTO、缓存和前端统一使用平台与套餐权限名称，禁止把套餐 ID 当作平台 ID。

### 全局余额倍率

全局余额倍率使用独立的全局计费设置保存，而非 `BillingProfile.group_id`。

- 余额请求使用全局余额倍率。
- 套餐请求使用订阅实例的倍率快照。
- 现有模型价格、渠道模型自定义价格、价格区间、图片/视频等定价逻辑保持原有解析方式。
- 迁移期保留旧 `BillingProfile` 只读兼容；新资产选择链路不得读取其余额倍率。

## 模型定价兼容

当前 `ModelPricingResolver` 先解析 Sub2API 的基础模型价格，再可按渠道覆盖价格。本次不重写该价格体系。

迁移期通过 `Platform.legacy_group_id` 将平台请求桥接到现有渠道定价上下文：

```text
模型与平台解析
  -> 现有 ModelPricingResolver
  -> 现有全局模型价格 / 已配置的渠道模型价格
  -> 套餐倍率或全局余额倍率
```

若同一平台存在多个旧 `Group` 或多个互相冲突的渠道定价来源，预检必须报告冲突，禁止自动选择其中一个。后续独立迭代再将渠道定价完全迁移为平台或全局模型定价配置。

## 使用记录与统计

新使用记录增加或优先使用以下事实字段：

| 字段 | 说明 |
| --- | --- |
| `platform_id` | 实际请求的平台 |
| `account_id` | 实际调用的上游账号 |
| `subscription_id` | 使用套餐时的实际订阅实例；余额请求为空 |
| `billing_source_type` | `subscription` 或 `balance` |
| `rate_multiplier` | 本次实际生效的资产倍率 |
| `cost` | 现有模型定价乘以实际倍率后的费用 |

旧 `usage_logs.group_id` 保留历史展示和迁移期兼容。新查询、筛选和聚合逐步改按 `platform_id` 与 `subscription_id`，避免将平台误显示为套餐。

## 前端体验

### 账号管理

- `CreateAccountModal` 与 `EditAccountModal` 删除 `GroupSelector`、`group_ids` 和混合分组风险检查。
- 账号列表的“分组”列改为“平台”，只展示账号自身平台。
- 批量编辑、导入、复制和影子账号流程不再写入账号分组关系。

### 平台管理

- 原“分组”管理界面改为“平台”管理界面。
- 一个平台配置对应一个平台账号池，维护模型白名单、端点能力和调度配置。
- 保存时校验模型白名单、模型映射别名和通配符不会与其他启用平台冲突。
- 旧复合分组和跨平台混合调度不进入新平台配置；迁移预检发现后要求人工拆分。

### API Key 管理

- 平台多选：展示可用平台。
- 扣费渠道：展示套餐多选与余额开关。
- 余额开关默认开启。
- 不再展示或编辑“分组”权限。
- 用户与管理员视图都显示已选的平台和扣费渠道，且不提供旧分组下拉回退入口。

### 套餐与订阅

- 套餐管理不再选择平台或分组。
- 用户订阅卡和使用记录展示套餐名称、套餐实例、额度、倍率与扣费来源。
- 可用渠道、模型广场、用户专属权限等涉及旧分组可见性的页面改按平台权限显示。

## 数据迁移与切换

采用四阶段迁移，不在首个版本删除旧表或旧字段。

### 阶段 0：只读预检

生成可下载或可查询的迁移报告，至少检查：

1. 同一客户端模型名、模型模式或映射别名出现在多个旧平台中的冲突。
2. 一个旧账号关联多个不同平台分组、复合分组或混合调度的冲突。
3. 同一平台存在多个候选旧 `Group`、渠道模型价格或余额倍率且无法安全合并的冲突。
4. 无法关联 `subscription_plan_id` 的有效旧订阅、兑换码和支付配置。
5. 无法从旧 API Key 分组映射到明确套餐权限、余额权限或任一平台的 Key。多个旧分组可明确映射到多个平台时不构成冲突，因为新 Key 允许多平台；一个旧分组对应零个或多个套餐时才必须人工确认。
6. 旧未绑定分组的 API Key；迁移不得默认为它授予全部平台权限。

任何冲突都只报告，不自动猜测、合并、删除或放大权限。

### 阶段 1：扩展结构与双读兼容

1. 新增平台、API Key 平台权限、API Key 套餐权限、全局余额倍率和使用记录平台字段。
2. 保留旧 `groups`、`account_groups`、API Key 分组授权、`BillingProfile.group_id`、订阅 `group_id` 和历史使用记录字段。
3. 新代码可读取新权限；新权限缺失时仅在明确可映射的旧数据上使用受限兼容读取。
4. 缓存版本递增，平台配置、Key 权限和订阅状态变化必须同时失效。

### 阶段 2：人工解决预检冲突

管理员为每个实际平台确认唯一平台配置与定价兼容来源，并修复重复模型名、旧复合配置、缺失套餐映射和无平台权限 Key。

此阶段完成前不得启用新调度链路。

### 阶段 3：切换新链路

1. 新增/编辑账号不再接受 `group_ids`。
2. 新增/编辑 API Key 只写平台权限、套餐权限与余额开关。
3. 网关按平台解析和平台账号池调度，再按资产来源扣费。
4. 新使用记录写入平台和资产来源事实字段。
5. 旧分组 API 保持只读或返回明确的迁移提示，禁止重新写入旧关系。

### 阶段 4：观察与清理

至少经过一个完整发布周期和业务验收后，再单独评估删除旧分组计费字段、`account_groups`、旧 Key 分组权限和历史兼容分支。该清理不属于本次实现范围。

## 错误语义

| 条件 | 结果 |
| --- | --- |
| 模型未归属任何启用平台 | 返回模型不可用错误 |
| 模型对应多个平台 | 配置错误，拒绝请求并提示管理员处理冲突 |
| API Key 未授权目标平台 | 返回权限错误，不尝试其他平台 |
| 平台没有可用账号 | 返回无可用账号，保持现有账号故障切换规则 |
| 允许套餐均无有效实例或均已耗尽，且余额允许且足够 | 使用余额 |
| 允许套餐均无效且余额未允许 | 返回无可用扣费渠道 |
| 余额允许但余额不足 | 返回余额不足 |
| 模型价格无法解析 | 保持现有 fail-closed 行为，不按默认 1 倍或 0 费用继续 |

## 验收与测试范围

1. 数据迁移：完整映射、冲突报告、无自动放权、可回滚。
2. 平台路由：模型唯一解析、平台权限拒绝、平台账号池、端点能力、账号故障切换。
3. 资产选择：多套餐最早到期优先、额度耗尽跳过、套餐到余额回退、余额关闭拒绝。
4. 计费：全局余额倍率、套餐快照倍率、两者不叠加、现有模型自定义价格不回归。
5. 并发：订阅额度临界扣减、缓存失效、同一用户多 Key 并发请求。
6. 记录：平台、账号、套餐实例、余额来源、倍率和费用归属正确。
7. 前端：账号表单无分组、平台配置模型冲突提示、API Key 两套独立选择器、余额默认开启。
8. 回归：`/v1/chat/completions`、`/v1/responses`、其他已支持平台端点、现有 OAuth 账号流程和 Docker 预发布。

## 风险与边界

- 这是持久化结构、网关调度和用户计费共同变更，必须在 `my2.0` 预发布通道验证，不进入 `my` 正式分支直到业务验收完成。
- 旧分组名称如“余额”“大包”“中包”不能自动推断为唯一平台配置；迁移以预检和人工确认优先。
- 本期不删除旧数据、不改变模型基础价格、不支持跨平台同名模型，也不恢复跨平台混合调度。
- `my2.0.drawio` 当前外层图页 XML 元数据不完整；其图主体已作为设计来源分析，但需要在 draw.io 中重新保存后再作为可解析的长期图文件。
