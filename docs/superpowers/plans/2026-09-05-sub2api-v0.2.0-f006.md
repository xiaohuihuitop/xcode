# Sub2API v0.2.0 F006 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不恢复官方 Group/Channel、迁移、前端或依赖的前提下，把 Sub2API `v0.2.0` F006 的共享重试、额度冷却、安全审计和原生 reasoning `max` 语义同步到 XCode 活动路径。

**Architecture:** 按 F006-A/B/C 三个独立提交实施。每组先写失败回归，再在 XCode Handler、Repository、SecurityAudit 或兼容转发边界做窄适配；已有平台路由、Ops 归属、IPv6 和 singleflight 能力只做等价验证。每组结束都归档同步清单、用冻结 snapshot rebaseline、恢复人工分类并运行双 validator。

**Tech Stack:** Go 1.26、Gin、PostgreSQL、`testify`、Python 同步工具、Git。

除明确写出仓库根目录的命令外，所有 `go test`、`go build` 和 `gofmt` 命令都从 `backend/` 执行。

---

## 文件职责

- `backend/internal/service/gateway_service.go`：携带同账号重试元数据，不改变 RuntimeBridge 公共契约。
- `backend/internal/handler/failover_loop.go`：统一决定同号重试资格、上限、deadline、delay 和请求级瞬态封禁行为。
- `backend/internal/handler/gateway_handler*.go`、`gemini_v1beta_handler.go`：从实际选中账号计算有效 retry limit。
- `backend/internal/repository/account_repo.go`：用单条 SQL 原子清额度并清账号级 rate-limit cooldown。
- `backend/internal/service/account_service.go`、`admin_account.go`：暴露并调用语义明确的窄 Repository 接口。
- `backend/internal/securityaudit/prompt_config_store.go`：仅在配置事实变化或错误恢复时记录 config loaded。
- `backend/internal/service/openai_gateway_request_body.go`：识别支持原生 `max` 的模型族。
- `backend/internal/service/gateway_forward_as_chat_completions.go`：按 mapped/original/body model 提取 Chat fallback reasoning effort。
- `backend/internal/service/gateway_forward_as_responses.go`：按 mapped/original/body model 提取 Responses fallback reasoning effort。
- 对应 `*_test.go`：锁定新行为和已有等价能力。
- `docs/upstream/sub2api-v0.2.0/`：保存每组审计、revision、功能矩阵和验证结果。
