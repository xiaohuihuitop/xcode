# My2 发布必须通过完整质量门禁

- 状态：已确认
- 日期：2026-08-11
- 结论：`my2-v*` Tag 只有在来源校验、后端 unit/integration、前端全量测试/typecheck/lint 和 Go lint 全部通过后，才允许发布版本镜像、离线包和 `my2-latest`。
- 原因：Tag 工作流与通用 CI 是独立触发的，不能依赖并行工作流的最终状态；必须在发布工作流内部形成不可绕过的 `needs` 门禁。
- 影响：`.github/workflows/my2-release.yml` 增加来源与质量门禁；`backend/Makefile` 的 integration 目标只运行真实集成包，避免旧 unit 夹具和 `tmp/ent` 生成目录污染集成编译；版本镜像先发布，GitHub Release 成功后才更新 latest。
- 相关文件：`.github/workflows/my2-release.yml`、`backend/Makefile`、`backend/internal/architecture/my2_release_gate_test.go`、`docs/superpowers/specs/2026-08-11-my2-release-quality-gate-design.md`

## 2026-08-12 门禁范围修正

- Go Lint 以生产正确性为发布阻断目标：保留 `depguard`、`errcheck`、`gosec`、`govet`、`ineffassign` 和 Staticcheck SA 正确性检查。
- `_test.go` 中的类型断言、Staticcheck ST/QF 风格建议、刻意验证 HTTP/2 原始小写键的 SA1008、迁移测试刻意调用旧密文 API 的 SA1019 使用显式范围排除。
- `unused` 在 Grok、Gemini、Anthropic、Live/WebSocket 等延期渠道仍保留兼容实现期间暂不作为发布阻断；对应渠道完成纯化后再分阶段重新启用，不得通过删除延期功能来满足本轮 OpenAI 发布。
- `backend/internal/architecture/my2_release_gate_test.go` 必须守卫上述边界，防止质量门禁被无意放宽或再次扩张为跨阶段重构门禁。
