# 平台调度命名空间与业务 ID 隔离

- 状态：已确认
- 日期：2026-08-10
- 结论：平台缓存命名空间与业务主键必须通过不同 helper 获取，禁止把 `PlatformSchedulingID` 写入任何持久化或业务身份字段。
- 原因：Platform 调度为避免与历史缓存键冲突使用 `-platform_id-1` 作为内部命名空间；该负数不是数据库 Platform 主键。混用会让 Ops、风控和 Live 记录出现无法关联的平台 ID。
- 影响：调度、粘连会话、并发槽位继续使用 `PlatformSchedulingID`；用量、Ops、风控、审计、Live 身份和其他数据库记录统一使用 `PlatformAssetID`。
- 相关文件：`backend/internal/service/platform_account_pool.go`、`backend/internal/handler/ops_error_logger.go`、`backend/internal/handler/openai_gateway_handler.go`、`backend/internal/handler/openai_live.go`

## 同步审查规则

- 同步官方代码后搜索 `PlatformSchedulingID`，确认每个调用点只服务于缓存、调度、粘连会话、并发或内部诊断。
- 新增持久化平台字段时，从 `PlatformSchedulingScope.PlatformID` 或 `PlatformAssetID` 取值，不得复用调度 namespace。
- Live 创建链路必须同时保留两个语义：`CreateLiveCall` 调度账号时传 `PlatformSchedulingID(ctx)`，`LiveCallIdentity.PlatformID` 和 `LiveCallRecord.PlatformID` 保持正数业务 ID。
- 脱离请求取消信号的异步用量、风控任务必须复制 `GatewayPlatformAssetContext`，不得直接从空 `context.Background()` 记录计费用量。
- 保留 `TestPlatformAssetIDUsesBusinessPlatformID`、`TestLiveCallIdentityUsesBusinessPlatformID`、`TestCreateLiveCallUsesSchedulingNamespaceAndKeepsBusinessIdentity`、`TestCreateLiveCallPersistsBusinessPlatformIDAfterScheduling` 和 `TestCyberPolicyRecordContextPreservesRouteAfterParentCancellation` 回归测试。
