# Sub2API 适配器纯化边界

- 状态：已确认
- 日期：2026-08-11
- 结论：Sub2API 继续作为唯一生产 Runtime；按端点分阶段移除 Adapter 内的 Gin carrier、公开 Handler 回调和 `legacyEndpointExecutor`，使生产 executor 只通过纯运行时请求、HTTP exchange、结构化结果和 UsageSink 工作。
- 原因：当前 ProductCore 与 Runtime 的公开契约已经隔离，但 Adapter 内仍把 Gin context 当作执行载体并回调旧 Handler。该兼容桥让协议实现、HTTP 入口和运行时所有权耦合，增加官方同步、回归定位和未来替换内核的成本。
- 影响：仅调整 Handler、Adapter 和现有 Sub2API service 的调用边界；不修改外部 API、数据库 schema、前端、平台/套餐/余额模型、定价与扣费语义，也不重写账号调度、OAuth、协议转换、流式处理、重试或失败切换算法。
- 实施原则：先建立纯 exchange 和端点契约，再按 CountTokens/Embeddings/Alpha Search、Gemini/媒体、Messages、OpenAI/Grok Chat/Responses、Live/WebSocket 的风险顺序迁移；每阶段保持单一生产路径并可独立回归。只有生产调用点归零后才能删除兼容桥。
- 验收：生产 executor 不接收或提取 `*gin.Context`；活动生产路径不调用 `legacyGinHandler`、`legacyEndpointExecutor` 或 `dispatchLegacyEndpoint`；终态用量 exactly-once、失败不扣费、实际端点、平台业务 ID 与调度命名空间均有回归测试。
- 相关文件：`backend/internal/handler/sub2api_legacy_dispatch.go`、`backend/internal/handler/sub2api_openai_executor.go`、`backend/internal/handler/sub2api_auxiliary_executor.go`、`backend/internal/handler/sub2api_messages_executor.go`、`backend/internal/gatewayruntime/`、`backend/internal/applicationgateway/`

## 2026-08-12 范围补充

- 本轮优先落地 OpenAI Images、Chat Completions、Responses 和 Messages；Grok、Gemini、Anthropic 其他入口以及 Live/WebSocket 延后，不为未接入渠道新增兼容逻辑。
- OpenAI 生产入口和 executor 只通过 `gatewayruntime.Request`、`HTTPExchange`、结构化结果和 `UsageSink` 连接；service 内部暂保留私有 `withRuntimeGinContext` seam，作为后续 transport-neutral 抽取的明确债务。
- `ApplicationGateway` 继续负责平台决策、套餐/余额授权和计费终态；Sub2API executor 只负责账号调度、OAuth、协议转换、流式转发和失败切换。

## 2026-08-12 OpenAI API Key 兼容路径落地

- OpenAI API Key 的原生 Chat、Responses->Chat、Messages->Chat 兼容路径使用 `context.Context + gatewayruntime.HTTPExchange`，共享纯 HTTP/SSE 管线，不再经过 service 私有 Gin seam。
- 兼容路径保留现有模型映射、套餐策略、上游鉴权、端点 marker、错误 envelope、failover、流式 usage 和客户端断开后的上游排空语义。
- 原生 Responses->Responses、OAuth/Codex 变换与 Live/WebSocket 不在本次抽取范围；这些路径继续使用旧 service seam，后续必须先补行为基线再迁移。
- 验证：`go test -tags=unit ./internal/service -count=1 -timeout=30m`、`go test -tags=unit ./internal/handler -count=1 -timeout=30m`、`go test -tags=unit ./internal/architecture -count=1 -timeout=30m` 均通过。
- 另有 Responses/Messages 流式兼容回归和纯交换层静态守卫，确保事件转换、usage、终止事件及 Gin seam 隔离不会回归。

## 2026-08-12 OpenAI 流式边界完成

- OpenAI 流式状态机已抽为无 Gin 的 `openAIStreamResponseSink + openAIStreamHooks` 核心，覆盖 SSE scanner、首输出 staging、客户端断线 drain、Codex/OAuth 事件转换、错误透传、超时、Cyber 标记、命名空间恢复和账号 failover。
- Gin 入口与 `gatewayruntime.HTTPExchange` 入口共用该核心；进入纯 exchange 核心前会同步 Forward 期间写入临时 Gin 上下文的 namespace/tool 状态，避免同一请求内状态复制时序造成工具名称丢失。
- 原生 `Forward` 的请求预处理、账号级协议选择和上游 HTTP 发送仍保留在 service seam，后续按 orchestration 单独抽取，不再重复迁移流式协议状态机。
- 验证：service、handler、architecture 全量回归、直接 exchange 成功/失败/首输出超时/namespace 测试及 `make test-unit` 均通过。

## 2026-08-12 原生 Responses HTTP attempt 抽取

- 原生 Responses 的上游 HTTP attempt 已进入纯 `context.Context + gatewayruntime.HTTPExchange` 核心，文件为 `backend/internal/service/openai_gateway_forward_runtime.go`。
- 纯核心负责标准请求发送、代理 URL、账号并发与实际账号绑定、上游延迟、传输/HTTP 错误分类、失败切换、JSON/SSE 响应处理、endpoint marker、请求 ID 和 usage 事实；生产 `Forward` 通过 exchange 接入该核心。
- 请求预处理、账号级协议选择、Passthrough/WSv2 以及 `Forward` 的外层 `withRuntimeGinContext` 兼容 seam 仍保留，不能把本切片记录为完整 transport-neutral orchestration；Grok、其他渠道和 Live/WebSocket 仍按用户确认延后。
- 验证：`go test -tags=unit ./internal/service -run 'TestForwardOpenAIHTTPExchange|TestOpenAIRuntimeForwardUsesNativeHTTPExchange|TestDoOpenAIUpstreamRequestExchangeUsesRuntimeSurface' -count=1`、OpenAI Service/Handler 定向回归、Architecture 纯化守卫、完整 `make test-unit`、`make test-integration` 和 `go build ./cmd/server` 均通过；本次完整单元测试中的 Service 包耗时 160.415s。

## 2026-08-12 普通 OpenAI Responses HTTP 预处理纯化

- 普通 OpenAI 原生 Responses HTTP/SSE 通过 `openai_gateway_forward_preparation_runtime.go` 使用 `context.Context + gatewayruntime.HTTPExchange`，不创建 Gin。
- 纯路径包含 Codex 客户端限制、Responses 工具/命名空间清理、模型映射、OAuth/Codex 请求变换、图片意图与计费元数据、fast policy 和客户端 stream 语义。
- `ForwardRuntime` 的纯路径门槛为 OpenAI 平台、Responses 能力有效、非 passthrough、非 compact、非 WebSocket；API Key 原生 Chat、Responses/Messages 兼容、compact、passthrough、WS 仍保留显式旧 seam，不能隐式 fallback。
- OAuth 上游可能被请求变换为 `stream=true`，但响应处理仍依据客户端原始 `stream`，这是必须保持的协议语义。
- 相关文件：`backend/internal/service/openai_gateway_forward_preparation_runtime.go`、`openai_gateway_runtime.go`、`openai_gateway_forward_runtime.go`、`openai_gateway_request_body.go`、`openai_gateway_service.go`；architecture guard 已纳入纯文件扫描。
