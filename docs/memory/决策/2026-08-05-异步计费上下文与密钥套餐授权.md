# 异步计费上下文与密钥套餐授权

## 状态

已确认根因并完成最小修复，待发布到 `my2.0` 预发布版本后进行真实请求验收。

## 现象

API Key 页面显示选择了平台、多个套餐和余额，但使用记录的分组为空，倍率回到 `1.0`，套餐用量没有变化。远端数据库核对发现该密钥存在平台授权记录，却没有任何 `api_key_subscription_plans` 关联记录。

## 结论

1. API Key 的套餐权限是显式关联，不会因为用户后来创建了有效订阅就自动回填到旧密钥。创建或编辑密钥后，必须确认 `api_key_subscription_plans` 已写入所选套餐；没有关联行时，套餐不会参与请求选择。
2. 平台资产网关在请求阶段已经解析出平台、计费来源、订阅或余额倍率和调度范围，但异步用量任务原先只复制请求 ID。请求结束后，计费服务读取不到平台资产上下文，于是使用记录缺少平台/来源归属，倍率回退到默认值。

## 实施

- 在 `backend/internal/handler/openai_gateway_handler.go` 的异步用量上下文包装器中复制 `GatewayPlatformAssetContext`。
- 保留后台任务独立的 `context` 生命周期，不把客户端取消信号带入计费任务。
- 不改变账号调度、OAuth 刷新、协议适配或套餐选择顺序；只修复已选资产在异步结算阶段的传递。

## 验收

使用专用测试密钥时，先在管理界面选择至少一个有效套餐和余额并保存；随后确认数据库存在对应的 `api_key_subscription_plans` 行。发送一次已配置账号支持的模型请求后，使用记录应出现平台和计费来源，倍率应等于套餐快照或全局余额倍率，套餐用量或余额应发生对应变化。

本地回归命令：

```text
go test -tags=unit ./internal/handler -run 'Test(OpenAI.*UsageRecordTask|UsageRecordContext)' -count=1
go test -tags=unit ./internal/service -run 'Test(OpenAIGatewayServiceRecordUsage_PlatformAssetUsesResolvedBalanceMultiplier|GatewayServiceRecordUsage_PlatformAssetUsesResolvedBalanceMultiplier|PlatformAssetBillingFactsOverrideLegacyGroupValues|GatewayPlatformAssetContext)' -count=1
go test -tags=unit ./internal/server/middleware -run 'TestPlatformAssetAuthorization' -count=1
```

## 后续同步检查

- 官方合并或重生网关处理器后，必须保留 `usageRecordContext` 对 `GatewayPlatformAssetContext` 的复制。
- 前端或 API Key 接口变更后，必须同时验证平台关联和套餐关联的持久化结果，不能只验证响应或页面状态。
- 真实测试应使用可撤销的专用 API Key；聊天中曾暴露过的密钥应在验收后立即撤销并重新生成。
