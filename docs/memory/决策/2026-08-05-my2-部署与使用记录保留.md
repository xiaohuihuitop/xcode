# My2 部署与使用记录保留

- 状态：已确认
- 日期：2026-08-05
- 结论：My2 测试服务器升级必须先完成可验证的 PostgreSQL 逻辑备份与配置备份；启动新版本后，`usage_logs` 的既有保留策略可能清理超过窗口的数据，不能误判为迁移删库。
- 原因：`DashboardAggregationService` 在启动后的聚合周期执行 `CleanupUsageLogs`，默认保留窗口为 90 天。`194_platform_assets_expand.sql` 是纯新增迁移，不包含使用记录删除语句。
- 验证：`my2-v0.2.1` 部署前后，用户、API Key、套餐、订阅、账号和旧分组数量保持一致；隔离恢复升级前备份后，确认生产缺失的 107 条使用记录全部早于 90 天截止点。
- 影响：后续 My2 发布前必须保留数据库备份，并将使用记录保留窗口作为独立运维决策。若要保留超过窗口的历史记录，必须先明确调整保留策略；仅恢复记录会在后续清理周期再次被删除。
- 相关文件：`backend/internal/service/dashboard_aggregation_service.go`、`backend/internal/repository/dashboard_aggregation_repo.go`、`backend/migrations/194_platform_assets_expand.sql`、`docs/memory/当前状态.md`
