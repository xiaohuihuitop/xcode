# 彻底移除旧分组配置

- 状态：已实施
- 日期：2026-08-09
- 结论：`my2.0` 不再保留 Group/Channel 旧配置、旧字段、旧 API 或运行时兼容回退；用户资产先一次性转换到 Platform、SubscriptionPlan 和余额模型，再物理删除旧 schema。
- 原因：旧分组仍参与认证、调度、计费、支付、安全策略和统计，造成双权威与不可预测回退；用户已明确允许放弃旧配置，不需要继续承担兼容成本。
- 影响：请求只依赖 Platform；API Key 只授权 Platform、套餐和余额；Account 只属于 Platform；模型价格迁到独立目录；安全策略和运维统计改用 Platform/Plan；旧 Group/Channel 管理入口和表最终删除。
- 数据保护：用户、API Key 本体、余额、套餐、订阅实例、支付和使用记录保留；有效旧资产无法转换时 migration 必须失败，不得静默删除。
- 保留能力：OAuth、协议适配、失败切换、Compact/Responses 技术配置、LiteLLM/静态价格、手工模型价格覆盖和 Channel Monitor。
- 相关文件：`docs/superpowers/plans/2026-08-09-remove-legacy-configuration.md`、`backend/internal/architecture/legacy_configuration_guard_test.go`、`backend/internal/service/model_pricing_catalog.go`、`backend/migrations/200_remove_legacy_configuration.sql`

## 最终实施结果（2026-08-10）

- Group、BillingProfile、CompositeModelRoute、旧 Channel 配置实体及其 Ent schema、repository、service、handler、路由和前端管理页已物理删除。
- API Key 只保留 `platform_ids`、`subscription_plan_ids` 和 `allow_balance`；Account 只归属 Platform，旧分组字段与账号普通模型策略不再读取或写入。
- Platform 成为路由、端点能力、模型规则和账号池的唯一权威；模型基础价格与手工覆盖由独立 `ModelPricingCatalog` 管理。
- SubscriptionPlan/UserSubscription 独立保存套餐额度和倍率；余额仅使用全局余额倍率。用量、Ops、风控、Prompt Audit 和通知模板统一使用 Platform/Plan 术语。
- migration 200 在转换仍有效的旧资产后删除旧列、旧表和旧设置；无法安全转换时直接失败，不静默丢失用户资产。
- 架构守卫禁止活动源码重新出现旧字段、旧设置、旧回退中间件和旧计费解析器；历史 migration 与专门验证“旧列已删除”的测试不属于运行时兼容。

## 计划审查结论

- 先迁移独立模型价格目录，再删除 Channel，避免丢失手工价格覆盖能力。
- 先转换有效订阅、兑换码和支付订单，再删除旧字段；无法确定转换关系时 migration 必须失败。
- 架构残留守卫在最终清理完成后创建并一次通过，不提交预期失败测试。
- 每个 Task 单独验证、最终统一精确暂存；`backend/entgen_tmp/`、`my2.0.drawio` 和非任务改动不得误入提交。
- 计划内表名已与 migration 081、082、101、106 核对；旧 migration 不修改，最终物理清理由 migration 200 执行。

## 取代的旧结论

- 取代“旧 Group 字段保留一个兼容周期”的策略。
- 取代“账号普通 model_mapping 作为回滚数据长期保留”的策略。
- 取代 Platform `legacy_group_id` 和 PricingGroupID 的只读桥接策略。
- 旧 migration 和历史设计文档只用于解释已发布版本，不再作为新实现依据。

## 真实数据库迁移补充（2026-08-10）

- 管理员可能在发行订阅兑换码后删除对应在售套餐；迁移必须按旧订阅条款生成 `for_sale=false` 的迁移套餐，再绑定有效订阅资产。
- 旧余额或套餐分组不是账号池，不得因历史审计记录而生成 `legacy-group-*` 平台；只有确实承载尚未迁移账号的旧账号池才可一次性转换为 Platform。
- 内容审核和运维原始记录必须保留；无法确认平台的旧维度留空。可重建的分组聚合行可移除，不得为保留聚合维度而复活旧配置。
- 发布前除单元测试外，必须用服务器备份在临时 PostgreSQL 副本中按实际顺序执行所有待升级 migration，并验证平台列表、订阅资产映射、旧表和旧字段的最终状态。
- Platform 的适配器字段是 `account_platform`；Ops 聚合、筛选、趋势和请求详情 SQL 不得引用不存在的 `platforms.platform`，该规则由 repository 契约测试保护。
