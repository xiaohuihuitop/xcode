# 官方同步与多套餐冲突处理

> 本文件记录 `my` 旧架构的发布行为。`my2.0` 的平台、套餐和余额授权不再使用
> `group_id` / `group_ids`；当前规则见
> [平台唯一入口与放弃旧配置](2026-08-06-平台唯一入口与放弃旧配置.md)。

- 状态：已确认
- 日期：2026-08-02
- 结论：同步 `upstream/main` 时以官方功能实现为基础，但必须保留多套餐调度、已确认 UI 定制和离线 Docker 发布能力。
- 原因：官方对 API Key 更新、鉴权缓存与 Docker 运行资源持续演进；直接选择任一冲突侧会丢失多套餐能力或新功能。
- 影响：后续官方同步应按以下规则处理：
  - API Key 保持 `group_id` 向后兼容，同时以 `group_ids` 管理多套餐；空 `group_ids` 允许不绑定分组。
  - API Key 更新采用官方的部分字段写入语义，IP 白名单和黑名单用指针区分“未修改”与“清空”。分组更新同时写入首分组 `group_id` 并替换多分组关联。
  - 鉴权缓存分组快照必须同时含多分组、OpenAI endpoint 能力、Live 开关及推理强度策略；字段增加时递增快照版本。
  - 用户密钥页面只在创建/编辑弹窗提供多套餐复选，表格分组保持只读展示，不恢复单分组下拉修改。`GroupOptionItem` 导入必须保留。
  - Dockerfile.goreleaser 同时保留二进制 `COPY --chown` 优化和 `backend/resources` 复制；release.yml 的 `v*` Tag 触发及 `sub2api_latest.tar` 产物不可移除。
- 验证方式：运行 API Key 服务/仓储/handler 定向 Go 测试；运行 KeysView、主题、侧边栏、订阅卡的前端回归测试，以及 `npm run typecheck`、`npm run lint:check`、`npm run build`。
- 相关文件：`backend/internal/service/api_key_service.go`、`backend/internal/service/api_key_auth_cache_impl.go`、`backend/internal/handler/api_key_handler.go`、`frontend/src/views/user/KeysView.vue`、`Dockerfile.goreleaser`、`.github/workflows/release.yml`。
