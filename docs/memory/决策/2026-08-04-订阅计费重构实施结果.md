# 订阅计费重构实施结果

> 后续状态：本文件只记录 `my2-v0.2.0` 的历史实现。余额倍率已改为全局配置；
> Group 路由、BillingProfile 和旧定价引用不再进入新请求。当前规则见
> [平台唯一入口与放弃旧配置](2026-08-06-平台唯一入口与放弃旧配置.md)。

- 状态：已确认并实施
- 日期：2026-08-04
- 结论：在 `my2.0` 将账号分组、余额计费资料、套餐模板和用户订阅实例拆分；新请求优先消耗可用套餐实例，全部不可用后才回退余额。
- 原因：同一个 `Group` 同时承载账号路由、收费规则和套餐权益，会导致配置耦合，且无法安全支持同组多条套餐实例。

## 领域边界

- `Group` 只承担平台、账号池、端点能力、调度、状态与 RPM 等路由职责。
- `BillingProfile` 一对一保存余额倍率、峰时、图片/视频/Web Search 等基础计价资料。
- `SubscriptionPlan` 保存每日/每周/每月额度、有效期和套餐独立倍率。
- `UserSubscription` 在发放时写入套餐名称、额度、有效期和倍率快照；同一用户可在同一分组拥有多条实例。
- 用户专属余额倍率不进入新计费路径；历史字段只作审计归档，不提供新请求兼容，RPM override 不参与平台或资产选择。

## 调度与兼容

- 按 API Key 的 `group_id` / `group_ids` 排序、平台和端点能力筛选分组；每个分组内按最早到期、再创建时间选择可用订阅实例。
- 一个实例过期、停用或达到日/周/月限额后继续尝试下一实例；全部实例不可用后，使用第一个可用分组的余额计费资料。
- 用量、缓存失效和套餐扣费以实际 `subscription_id` 归属，避免同组多实例混用额度。
- 旧 `Group` 收费字段和旧订阅配置在迁移周期内保持读取回退；新建/编辑流程只写 `BillingProfile`、套餐模板和实例快照。

## 回归保护

- 可选 `*SubscriptionService(nil)` 传入接口时必须视为未注入服务，安全回退余额，不能 panic。
- `/v1/sub2api/billing` 是只读鉴权接口：跳过订阅/余额/额度检查与最后使用时间写入。
- OpenAI `chat/completions` 与 `responses` 继续使用端点能力筛选，不同兼容分组可独立调度。
