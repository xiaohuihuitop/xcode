# 运行时适配器边界与可替换内核

- 状态：已确认
- 日期：2026-08-10
- 结论：先将现有 Sub2API 收口为进程内 `Sub2APIRuntimeAdapter`，完成 ProductCore、Runtime、Pricing 和 Usage 边界后，再评估或接入其他内核。
- 原因：平台、套餐、余额和 API Key 已成为自有 ProductCore，而账号调度、OAuth、协议和失败切换仍高度依赖 Sub2API；直接替换会同时触碰路由、用量和计费，风险过高。
- 影响：第一阶段只建立行为不变的契约与适配器，不改外部 API、数据库 schema、前端、Docker 或现有请求语义，也不接入第二套内核。
- 相关文件：`docs/superpowers/specs/2026-08-10-runtime-adapter-boundary-design.md`、`backend/internal/productcore/`、`backend/internal/gatewayruntime/`、`backend/internal/service/gateway_runtime_bridge.go`

## 长期边界

- ProductCore 独立决定 Platform、模型、端点、API Key 授权、套餐或余额和资产倍率。
- GatewayRuntime 只负责账号、OAuth、调度、协议转换、流式传输、重试和失败切换。
- PricingEngine 独立于传输 Runtime，默认继续包装当前 Sub2API 模型价格目录。
- UsageSink 属于 ProductCore 基础设施；Runtime 只报告 UsageFacts，不决定用户资产扣费。
- ProductCore 与 runtime contract 禁止导入 Gin、Ent、`internal/service` 或具体 Sub2API 类型。
- 生产请求只允许一条 ApplicationGateway 路径，不保留失败后回旧实现的静默 fallback。

## 迁移约束

- 已部署的自定义迁移 `192-200` 永久冻结。
- 后续官方适配迁移使用 `8000-8999`，ProductCore 自有迁移使用 `9000-9999`。
- 不直接复制与当前分支冲突的官方迁移文件；必须按当前 Platform/ProductCore schema 审查并重新命名适配。

## 验收约束

- 先建立现有行为契约测试，再切换调用入口。
- 成功请求只扣一次，失败请求不扣费。
- Chat、Responses、Messages、Gemini、OAuth、失败切换、平台隔离和套餐/余额计费均需回归。
- 完成全量测试、离线镜像和腾讯云两轮真实验收后，适配器边界阶段才算完成。

## 本次实现进展（2026-08-10）

- 已建立纯标准库 `gatewayruntime` 合同、`applicationgateway.Gateway`、Sub2API 运行时适配器、Pricing 适配器和 Product Usage Sink；这些合同不携带 API Key、用户、订阅、余额、倍率或 Ent 实体。
- Messages、Chat Completions 和 Responses 的生产 HTTP 入口已统一组装到一个共享的 `ApplicationGateway -> Sub2APIRuntimeAdapter`。现有 Gin handler 仍作为兼容执行器，Gin bridge 只允许存在于适配器边界内，便于后续逐端点提取纯 executor。
- 现有终态计费仍由 Sub2API billing service 执行；Runtime 只上报 `UsageFacts`。成功请求保持只记录一次，失败请求不扣费；worker 会复制已解析的平台/计费上下文和 UsageSink。
- 运行时同步迁移规则已固化：`001-200` 不可修改，未来 Runtime 使用 `8000-8999`，ProductCore 使用 `9000-9999`，并由架构测试固定 `192-200` SHA256。

## 尚未完成

- Gemini、媒体、CountTokens、账号探测、Live 和 Responses WebSocket 尚未全部迁移到同一纯 executor 合同；当前仍通过兼容 handler 保持原有行为。
- OpenAI 多协议的实际上游 endpoint marker 已在主要转换入口设置，但仍需补齐每个 failover attempt 的跨协议回归覆盖后，才可声明端点边界全部完成。
- 尚未执行本阶段的 Git 提交、Tag、远程推送、Docker 发布或腾讯云真实环境验收。
