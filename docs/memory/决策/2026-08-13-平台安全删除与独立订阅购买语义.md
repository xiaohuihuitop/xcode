# 平台安全删除与独立订阅购买语义

## 决策

- 平台采用“受控级联删除”：账号或 API Key 存在引用时返回 `PLATFORM_IN_USE`；仅有使用、审计、运维和平台范围配置引用时，系统自动清理这些历史引用后删除平台。
- 不提供绕过账号/API Key 检查的强制删除，也不自动解绑账号或 API Key。历史清理、平台范围设置更新、模型规则删除和平台删除必须在同一个 PostgreSQL 事务内完成，失败全部回滚。
- 管理端“订阅套餐”入口改名为“上架订阅”。
- 再次购买同一套餐会创建一份新的独立订阅，不延长原订阅时长；多份订阅并存并按系统既定顺序使用。
- 重复购买按钮使用“再来一个”，不使用“续费”。

## 实现边界

- 后端通过 `PreviewDelete` 提供只读影响预览，通过 `DeleteControlled` 在锁定平台后重新统计；预览结果不能作为删除授权。
- 受控删除必须兼容历史部署中未安装的可选运维表：存在时纳入锁定、计数和清理，不存在时按零引用处理；不得因可选表缺失返回 500。
- 历史清理只覆盖目标平台的使用记录、Prompt Audit、内容审核、调度 Outbox、运维记录、告警及平台范围设置。用户、余额、订阅、订单、CDK、账号和 API Key 不得被该路径删除。
- 前端平台页必须在二次确认中显示永久清理数量；账号或 API Key 仍绑定时确认按钮禁用，最终 DELETE 仍须处理并发新增引用导致的 `409`。
- 充值/订阅页面在套餐列表与订单确认阶段都展示独立叠加说明。

## 验证

- 后端：Platform service/repository/admin handler/routes 单元测试；真实 PostgreSQL 集成测试验证目标清理、对照平台隔离和设置 JSON 保留。
- 生产数据库：部署前备份；先预览一个无账号、无密钥的旧平台，再删除并核对其他平台与用户资产不变。
- 前端：平台删除预览、阻断、确认、并发冲突与中英文文案测试；typecheck、lint、production build。
