# 套餐独立扣费不依赖旧分组

> 后续修订：套餐扣费不依赖 Group 的结论继续有效；旧 `group_id` 字段不再作为新架构
> 的兼容输入，只可在物理清理前为历史记录保留。

日期：2026-08-06

## 触发信号

平台与套餐授权保存成功、真实请求也能完成，但异步记录用量时报 `SUBSCRIPTION_NOT_FOUND`。

## 根因与约束

新的 `user_subscriptions` 可以不绑定 `group_id`，套餐用量只由订阅实例自身承载。统一计费仓储和降级仓储仍通过 `JOIN groups` 判断订阅有效，导致无分组套餐无法累加用量。

## 决策

- 套餐扣费和用量累加只按订阅实例 `id` 与 `deleted_at IS NULL` 更新，不再依赖旧 `groups` 表。
- 旧 `group_id` 字段只在物理清理前保留历史事实；无论是否有值，Group 状态都不能阻断新套餐实例扣费。
- 统一计费路径与 `UserSubscriptionRepository.IncrementUsage` 降级路径必须保持同一规则。

## 验证方式

- 仓储单测覆盖无分组订阅的原子用量更新 SQL。
- PostgreSQL 集成测试覆盖无分组订阅和旧分组软删除后的用量累加。
- 真实 API 请求需同时检查 200 响应、`usage_logs` 订阅归属和订阅额度递增。

## 适用范围

后续同步官方版本或重建计费仓储时，不能恢复 `JOIN groups` 作为套餐扣费前置条件。
