# 平台授权与套餐管理可达性

- 状态：已确认并实施
- 日期：2026-08-05
- 结论：API Key 的平台授权列表必须由已注入的 `PlatformService` 提供；订阅套餐模板管理独立于在线支付开关，管理员始终可创建、编辑和管理套餐。

## 原因

平台、账号和模型规则在测试服务器中均正常存在，但生成的 Wire 代码仍调用旧版
`NewAPIKeyHandler(apiKeyService)`，没有为 `/api/v1/platforms/available` 注入平台池读取能力。
前端将接口错误回退为没有可选平台，造成“平台池已添加但密钥不能选择”的假象。

套餐模板本身是 V2 的资产定义，不是在线收款功能。原先它只位于受
`payment_enabled` 控制的订单菜单中，且路由带有 `requiresPayment`，导致关闭在线支付时管理员无法配置套餐。

## 已确认约束

- `NewAPIKeyHandler` 必须接收 `platformPoolLister`。不得恢复为无平台池依赖的构造函数。
- `handler.ProviderSet` 必须使用 `ProvideAPIKeyHandler`；修改依赖提供者后必须运行
  `go generate ./cmd/server` 并提交重新生成的 `backend/cmd/server/wire_gen.go`。
- `/admin/orders/plans` 必须保持管理员可访问且不带 `requiresPayment`；侧栏必须有独立“订阅套餐”入口。
- `/admin/orders` 和 `/admin/orders/dashboard` 仍是在线支付运营功能，应继续受支付开关控制。
- 用户创建 API Key 时，平台是必选的调度范围；套餐和余额是独立的计费来源。没有有效套餐时可以只选择平台并保留默认余额授权。
