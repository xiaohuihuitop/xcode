# 全局余额倍率与旧分组兼容

> 2026-08-06 修订：历史订单与审计数据仍需保留，但旧 Group 不再参与新请求、平台选择、
> 模型定价或资产倍率。本文的旧路由/API 兼容要求已由
> [平台唯一入口与放弃旧配置](2026-08-06-平台唯一入口与放弃旧配置.md)替代。

## 历史订单回退（2026-08-05）

旧支付订单可能同时保存已失效的 `plan_id`，以及历史 `subscription_group_id` 和订阅天数快照。同步官方或重构套餐逻辑时，必须保留以下回退规则：

- 履约时若套餐不存在，且旧分组与天数快照齐全，则按旧分组授予或恢复订阅。
- 购买成功通知优先读取有效套餐/套餐实例；两者都不可用时，回退展示旧分组名称和旧分组订阅到期时间。
- 退款预扣优先扣回套餐实例；找不到套餐实例但旧分组与天数快照齐全时，扣回旧分组订阅。没有旧快照的 V2 订单仍要求强制退款确认，不可猜测替代资产。

回归测试：`TestExecuteSubscriptionFulfillmentFallsBackToLegacyGroupWhenPlanIsMissing`、`TestSubscriptionPurchaseNotificationVariablesFallBackToLegacyGroupWhenPlanIsMissing`、`TestPrepDeductFallsBackToLegacyGroupWhenPlanIsMissing`。

- 状态：历史实现已完成；旧路由兼容部分已被替代
- 日期：2026-08-05
- 分支：`my2.0`

## 决策

1. V2 余额只使用全局设置 `global_balance_rate_multiplier`；不再按分组、用户或峰时配置余额倍率。
2. V2 套餐只使用 `UserSubscription` 发放时保存的倍率快照。套餐倍率和余额倍率只取其一，绝不叠乘。
3. 平台资产请求进入网关后，`ResolvedBillingAsset.RateMultiplier` 必须覆盖旧 API Key / `Group` / `BillingProfile` 的 token、image 和 video 倍率。
4. 第一阶段曾用 `Platform.legacy_group_id` 提供模型定价上下文；新设计必须改为独立模型定价目录，不得继续把 Group 带入新请求。
5. 新账号和 Spark shadow 账号只属于 `platform_id` 对应的平台池；不得创建、继承或默认补写 `account_groups`。
6. 管理端不再在旧分组页面展示余额计费入口。全局余额倍率在套餐管理页配置，套餐倍率在套餐自身配置。

## 历史兼容边界（已停止扩展）

- 被支付订单、退款审计或历史用量引用的旧行只读归档，不能因为放弃路由配置而直接硬删除。
- 旧 Key 不再走 Group 路由；没有平台授权时直接拒绝请求。
- 旧 Group 自定义价格不迁移，管理员在独立模型定价目录重新录入需要保留的价格。
- 旧管理路由和 API 在新路径完成且代码引用清零后删除；只读归档不等于运行时兼容。

1. 先保留官方功能和迁移，再恢复 V2 平台资产权限与全局倍率注入。
2. 检查两套网关记录用量前是否调用平台资产倍率覆盖。
3. 检查账号和 Spark shadow 创建/编辑流程不会重新写入 `group_ids`。
4. 检查旧分组页面、旧路由 API 和 Group 定价入口没有重新进入新请求链路。
5. 运行本文件列出的回归测试，以及发布前的类型检查、lint、构建和差异检查。
