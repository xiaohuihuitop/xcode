# 平台与资产解耦

- 状态：已确认
- 日期：2026-08-04
- 结论：平台只承担账号池、模型白名单、接口能力和调度；套餐与余额是跨平台的用户资产；API Key 独立选择可用平台、可用套餐和是否允许余额。

## 原因

原有 `Group` 同时表示账号池、API Key 权限、套餐权益和余额计费，导致“余额/大包/中包”等资产名称被错误展示为账号分组，也使账号调度与套餐扣费相互耦合。

## 已确认约束

- 每个平台只有一个账号池，账号不能跨平台混用。
- 客户端可见的模型名、模型模式和映射别名不能跨平台冲突。
- 新建 API Key 默认允许余额，但余额仍是可显式关闭的扣费渠道。
- 同一 Key 的有效套餐实例按最早到期、再创建时间优先；套餐不可用后才使用已允许的余额。
- 套餐倍率与全局余额倍率不叠加。
- 模型基础价格和自定义模型收费继续由 Sub2API 现有定价体系处理。
- 历史方案曾要求迁移期兼容读取旧分组；该约束已于 2026-08-06 废止。旧行只可为历史和审计归档，不参与新请求。

## 影响

- 账号表单、账号调度、平台配置、API Key 权限、套餐权益、余额倍率、使用记录和数据迁移均需调整。
- 先在 `my2.0` 预发布通道完成迁移和业务验证，不直接进入 `my` 正式交付分支。

## 后续修订

2026-08-06 已确认测试环境旧路由配置可以放弃。本文件关于“迁移期兼容读取”和旧分组预检的约束，由[平台唯一入口与放弃旧配置](2026-08-06-平台唯一入口与放弃旧配置.md)替代；平台与资产解耦、套餐优先和余额回退等领域结论继续有效。
