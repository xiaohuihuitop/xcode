# 订阅套餐耗尽即时回退

> “套餐耗尽后自动尝试下一实例、最后回退余额”的行为继续有效；本文依赖不同
> `group_id` 的数据模型只适用于旧版本。My2 当前按独立套餐实例选择资产。

## 触发信号

- API Key 同时绑定多个订阅套餐时，优先套餐用尽后，下一次请求可能仍被分配到该套餐并返回限额错误。

## 根因与约束

- 订阅认证 L1 缓存默认有 TTL；成功扣费后若不立即失效，调度器会使用旧的用量快照。
- 调度前的 `ValidateAndCheckLimits` 原先允许“用量等于额度”，但实际扣费缓存以 `>=` 将其视为已耗尽，二者语义不一致。
- 实际扣费已知本次费用时，保留 `CheckUsageLimits` 的 `<=` 逻辑，以允许单次请求恰好消耗完剩余额度。

## 正确做法

- 每次订阅套餐成功扣费后，立即失效本机订阅认证 L1，并发布跨实例失效通知。
- 调度前未知费用时，日、周、月用量达到或超过限额即跳过该套餐，继续按既有排序选择下一个可用套餐或余额分组。
- 不改变同一 `group_id` 只能拥有一条订阅记录的官方数据模型；多份可切换订阅应是不同的套餐分组。
